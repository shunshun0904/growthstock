# 1行目で実験17（TabICLv2）の実行内容を指定する。
#
#   probe                        所要時間とメモリの実測・外挿だけ。本走はしない
#   run [上限] [数] [同時] [種]  本走
#                    上限 = 文脈に入れる訓練行の上限（0 で全行）
#                    数   = TabICL 内部のアンサンブル数（既定8）
#                    同時 = 同時に流すアンサンブル数（既定2）。
#                           メモリの上限を決める。精度は変わらない
#                    種   = カンマ区切り（既定 42）。既存5モデルは 42,7,123
#   no                           何もしない
#
# 例:
#   probe
#   run 0 8 2 42,7,123   全訓練行・アンサンブル8・既存5モデルと同じ3種
#   run 8000 4 1 42      直近8,000行に絞り、アンサンブル4・同時1・1種
#                        （CPU の予算やメモリが足りないとき）
#
# いまの設定を選んだ理由
# --------------------
# 文脈を絞らないのは、絞ると TabICL だけ訓練行の一部しか見ないことになり、
# 既存5モデルとの比較に手法以外の差が入るため。実測で全行でも回るので、
# わざわざ不利な条件を作る理由がない。
#
# 種を 42,7,123 にしたのは、既存5モデル（実験16）と同じにするため。
# 種平均はそれ自体がアンサンブルなので、TabICL だけ1種にすると
# 既存5モデル側に有利な比較になる。
#
# なぜ最初が probe か
# ------------------
# TabICL は GPU 前提の設計（H100 で 50,000行×100列を10秒未満）で、
# CPU で何倍掛かるかは公表されていない。全10窓を回してから
# 「6時間で終わらなかった」と分かるのは、CI の実行1回を捨てることになる。
# 先に文脈の行数を変えて実測し、外挿してから設定を決める。
#
# 本走は窓ごとに out-of-fold を書き出し、data-raw Release に持ち回す。
# 予算切れで止まっても、もう一度走らせれば残りの窓から続く。
#
# 履歴:
#   2026-09-14 probe … CI で実測
#                      文脈1,000行 / 検証500行 / アンサンブル2 / 同時2  16.9秒
#                      文脈3,000行 / 検証500行 / アンサンブル2 / 同時2  33.6秒
#                      -> 文脈1行あたり 8.39ミリ秒 / 固定費 8.5秒
#                      -> 全窓・全訓練行(19,726)・アンサンブル8 で 1.4時間
#                      最大メモリは2点とも 5.39GB で動かず。TabICL の確保ぶんが
#                      lab.frame() のデータフレームに埋もれているため、
#                      これは下限であって見積もりではない
#   2026-09-14 run   … 全訓練行・アンサンブル8・同時2・3種で本走
#                      -> 18分でランナーごと落ちた（exit 143 / SIGTERM）。
#                         メモリ不足。`if: always()` を付けた「途中結果を
#                         Release に戻す」まで飛ばされ、計算が丸ごと消えた。
#                         出力もバッファに残ったまま消え、どの窓で落ちたのか
#                         すら分からなかった。
#                         原因は probe の条件が本走と違ったこと。
#                         probe: アンサンブル2 / 同時2 / 検証500行
#                         本走  : アンサンブル8 / 同時2 / 検証1,400行
#                         さらに最高水位が lab.frame() の 5.4GB に埋もれ、
#                         メモリの増加そのものが見えていなかった。
#   2026-09-14 probe … 直して測り直す。本走と同じ条件（アンサンブル8）で、
#                      窓ごとに最高水位をリセットし、同時1 に下げる。
#                      出力は1行ずつ（PYTHONUNBUFFERED）、上限13GB で
#                      ランナーではなく Python を止める
