# 全特徴量の点検（実測・2026-09-22）

運用者の指示「学習や検証に入る前に改めて全特徴量の EDA をお願いします」に対する記録。

- 列そのものの性質（欠損・外れ値・分布・冗長）: `research/eda_stats.py` → `research/eda.json`
- 検出力（その列に意味があるか）: `research/exp/e40_feature_eda.py` → `research/_data/oof/e40_feature_eda.csv`

母集団 21,856件 / 銘柄 3,735 / 2018-04-03〜2026-08-21。
物差しは `ret_o1_20`（翌日始値で入り、20営業日後の5日平均終値で出る）。

## 測り方

実験20・23 と同じ。本番の out-of-fold と同じ11窓（36ヶ月訓練 / 6ヶ月テスト /
6ヶ月刻み、エンバーゴ20営業日）で、窓ごとに

- **上位 z** … その列の上位10%の実収益が、同じ窓の平均をどれだけ上回ったか
- **下位 z** … その列の下位10%の実収益が、同じ窓の平均をどれだけ上回ったか

を取り、11窓ぶんの 平均 ÷ 標準誤差 を z とする。足切りは |z| > 2。
ノイズ床は 0.143pt（実験11）。

特徴量が205本あるので偶然の |z|>2 は数本出る。**1本だけの |z|>2 は採らず、
同じ群の中で符号が揃うかで読む。**

## 結論を先に

1. **買う理由になる列は18本、見送る理由になる列は38本。** 片側にしか効かない列が
   多いという実験37 の結論が、全特徴量でも成り立つ。両側とも効く（高いほど良く
   低いほど悪い、という単調な）列は9本しかない
2. **いちばん強いのは #45 で足した `rev_up_n_250`（直近250営業日の上方修正の回数）。**
   上位 z=+4.06 / +0.91pt / 11窓中9窓で勝ち。下位も z=−3.62 なので単調。
   買う理由18本のうち、本番の153列に入っていないのは `rev_up_n_250` と
   `rev_n_250` の2本だけで、**その2本がいちばん上に来た**
3. **地合いの11列（`market` 群）は別扱いで読む。** この11列は同じ日ならどの銘柄でも
   同じ値であることを実測した。「上位10%」は「その窓の中で相場が高かった日」であり、
   測っているのは銘柄の選別ではなく**時期の選別**。全体で最大の |z| を出した
   `topix_ma200_gap`（4.55）もこれに当たる。同じ日の行は独立ではないので、
   z は見かけほど強くない
4. **年ごとの欠損率のブレは、初年度だけの話だった。** 全期間で40pt超動く列は36本
   あるが、**そのすべてで最悪の年が2018年**であり、2018年を外すと1本も残らない。
   4四半期の履歴や6ヶ月前の高値が要る列は母集団の開始直後には作れないというだけ。
   しかも 2018年は最初のテスト窓（2021-05）より前なので評価には一度も使われない
5. **44列はまだ測れない。** #47〜#50 の7つ（valuation / 大量保有 / 大株主 /
   政策保有 / 信用規制 / 決算予定 / 投資部門別）はバックフィル中で全行欠測。
   この文書の結論は残る161列についてのもの

## 7. ラベルの内訳

定義は `1ヶ月内+1.2σ / 終盤+0.50倍 / MA5>=MA20`。
**到達しきい値は固定%ではなく銘柄自身の期間σの1.2倍**なので行ごとに違う
（中央値 10.95%、四分位 7.59%〜17.44%）。

| | 件数 | 割合 |
|---|---:|---:|
| 母集団 | 21,856 | 100% |
| 到達 | 5,176 | 23.7% |
| 正例 | 3,865 | 17.7% |
| 到達したのに継続条件で落ちた | 1,311 | 到達の25.3% |
| 到達していないのに正例 | 0 | — （整合） |

年ごとの正例率は 12.8%（2018）〜 22.6%（2025）。
評価に使う11窓では 9.1% 〜 26.1% と3倍近く動く。
順位で選ぶ規則（`pctHistorical`）はこの差の上で働いている。

### eda_stats.py のバグ（2026-09-22 に直した）

この内訳は直前まで壊れていた。

```
到達 2,293件 → 正例 3,865件   ← 到達より正例が多い
```

原因は `label_stats` が固定の `cfg.threshold`（20%）で到達を測っていたこと。
本番のラベルはボラ正規化なので、実際のしきい値は行ごとに違い、
**80.3% の行で 20% より緩い**。`build_dataset.rise_thresholds` が式の正本なので、
`vol_20d` からそこを呼んで引き直す形に直した。

`build_dataset` は `rise_need` を列として残しているが `FUTURE_COLS` に
入っていないため、データセットには出ていない。`vol_20d` は残るので、
後段は必ず `rise_thresholds` から引き直すこと。
