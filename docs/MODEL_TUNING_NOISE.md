# 週次のパラメータ探索は、どれだけ結果を動かすか（実測・2026-09-19）

## 結論を先に

1. **信用残を直したデータにしても、成績は測れるほど変わらない。** 同じ
   パラメータで比べると `ret_o1_20` で +0.08pt（z +0.09）、`ret_o1_40` で
   +0.29pt（z +0.34）。足切り（z>2）に遠い。**害も無い**ので、直したデータを
   そのまま使ってよい。
2. **いちばん大きく結果を動かしていたのは、探索の引き直しそのものだった。**
   同じデータ・同じ条件で Optuna の種だけを変えると、窓平均が
   **0.60〜1.54pt** の幅で散る。実験11 で測ったノイズ床（モデルの種だけを
   振ったときの 0.143pt）の **4〜11倍**。
3. **「複数回探索して平均する」では解決しない。** 4本の引きのスコアを
   平均しても `ret_o1_40` は改善ゼロで、最悪の窓は −9.28pt とどの個別の
   引きより悪化した。
4. **ただし、どのやり方が良いかは決着していない。** 旧データ側と新データ側の
   分布は大きく重なり、平均の差は z −0.94。足切りを越えたものは1つも無い。

> **追記（2026-09-21、実験25）**: 現行のラベル（1ヶ月内 +1.2σ）・物差し
> `ret_o1_20`・本番パラメータで種5つを振り直すと、窓平均のレンジは
> 0.59pt（1種）/ 0.67pt（3種平均10通り）だった。本文の「0.143pt（実験11）」は
> 旧ラベル・出口40営業日での値で、現行の設定には当てはまらない。
> 採否の規則は `docs/MODEL_ADOPTION_RULES.md`。

## 何をどう測ったか

信用残の取りこぼしを直して全期間を取り直した（`docs/OPERATIONS.md`）。
その前後のデータセットを両方残し、**共通行だけ**に揃えて比べた。

```
旧データ 21,779件 / 2018-04-03 〜 2026-08-13
新データ 21,856件 / 2018-04-03 〜 2026-08-21
共通行   21,779件（旧は新の完全な部分集合。増えたのは末尾の77行）

共通行のうち値が変わった列
  credit_ratio   633件 (2.91%)
```

**変わったのは特徴量1本の2.91%の行だけ**で、ラベルも他の150特徴量も
1件も動いていない。`credit_ratio_r`（横断面順位版）は410件変わっているが、
`all` プリセットに入っていないのでモデルは見ていない。

探索は本番と同条件（`run_tuning.py --n-trials 50 --cv year_cap_date
--n-splits 5`、ホールドアウトより手前で打ち切り）。out-of-fold は
`train_production.py` と同じ窓（36ヶ月 / 6ヶ月 / 6ヶ月・エンバーゴ20営業日）。
差が小さいので OOF はモデルの種3つ（42 / 7 / 123）の確率平均にした
（本番は単一種）。

**本番の `research/lgbm_params.json` には書いていない。**
探索結果は `research/_data/oof/e19*_params.json`。

## 実験19: データを新しくすると何が起きるか

| 条件 | データ | パラメータ | `ret_o1_20` | `ret_o1_40` |
|---|---|---|---|---|
| A | 旧 | 旧で探索 | +1.20pt | +1.33pt |
| B | 新 | **A と同じ** | **+1.28pt** | **+1.62pt** |
| C | 新 | 新で探索 | +0.50pt | +0.70pt |

```
A -> B（データだけを新しくした）  +0.08pt / z +0.09 → 差なし
B -> C（その上で探索を引き直した） -0.78pt / z -0.80 → 差なし
```

データの差より、**探索を引き直した差のほうが10倍近く大きい**。
どちらも足切りは越えていないが、大きさの桁が違う。

## 実験19b / 19c: 探索の種だけを振る

同じデータ・同じ行・同じ条件で、Optuna の種を 0/1/2/3 の4通りに振った。
旧データ側・新データ側の両方でやり、2つの分布を並べた。

### 実収益 `ret_o1_20`（窓平均）

| 探索の種 | 旧データ | 新データ |
|---|---|---|
| 0 | +1.20pt | +0.50pt |
| 1 | +1.28pt | +1.10pt |
| 2 | +1.18pt | +0.89pt |
| 3 | +0.43pt | +0.72pt |
| **平均** | **+1.02pt** | **+0.80pt** |
| レンジ | 0.85pt | 0.60pt |
| 標準偏差 | 0.40pt | 0.26pt |

### 実収益 `ret_o1_40`（窓平均）

| 探索の種 | 旧データ | 新データ |
|---|---|---|
| 0 | +1.33pt | +0.70pt |
| 1 | +1.85pt | +1.23pt |
| 2 | +0.89pt | +0.59pt |
| 3 | +0.31pt | +0.48pt |
| **平均** | **+1.10pt** | **+0.75pt** |
| レンジ | 1.54pt | 0.75pt |
| 標準偏差 | 0.65pt | 0.33pt |

```
平均の差（新 - 旧）  ret_o1_20  -0.22pt / z -0.94 → 差なし
                    ret_o1_40  -0.34pt / z -0.94 → 差なし
```

**実験19b だけを見たときの「新データの4本すべてが A を下回った」は、
A が自分の分布の上位（4本中2位）にいただけだった。** 旧データ側も
同じかそれ以上に散り（レンジ 0.85 / 1.54pt）、最悪の引きは +0.43 / +0.31pt
と新データ側のどの引きより低い。2つの分布は大きく重なっている。

探索したパラメータ自体も大きく振れる。同じデータ・同じ条件で:

```
新データ  葉 21〜80（4倍） / min_child_samples 64〜200（3倍） / lr 0.0139〜0.0247
旧データ  葉 34〜68        / lr 0.0120〜0.0187
```

## 探索のCV は、正直な評価を予測しない（ただし逆相関でもない）

探索が最大化しているのは層別k分割の PR-AUC。それが out-of-fold や実収益の
順位をどれだけ当てるかを、8本の引きで見た（n=4 ずつなので参考値）。

| | 旧データ | 新データ | 8本まとめて |
|---|---|---|---|
| CV vs OOF PR-AUC | +0.40 | **−0.80** | −0.52 |
| CV vs 実収益 `ret_o1_20` | +0.40 | +0.40 | +0.29 |
| CV vs 実収益 `ret_o1_40` | +0.40 | +1.00 | +0.52 |

**新データ側だけを見ると CV と OOF PR-AUC は ρ −0.80 だが、旧データ側では
+0.40 で、再現しない。** 実収益との相関は両側とも正（+0.40 / +0.40〜+1.00）。
n=4 の順位相関なので、どれも「弱くてばらつく」以上のことは言えない。
**「探索のCV は当てにならない」までは言えるが、「逆を向いている」とは
言えない。**

一方、8本を通して安定して負なのはこちら。

```
実収益 ret_o1_20 vs 日内AUC   ρ = -0.67
実収益 ret_o1_20 vs OOF PR-AUC ρ = +0.14
```

**日内AUC が高い引きほど実収益が低い。** 実験14・18b・18c で繰り返し
見てきた「AUC と実収益が一致しない」が、同じモデル・同じデータの
8本の引きの中でも出ている。

## 「複数回探索して平均する」は効かなかった

4本の引きの OOF スコアを平均して（追加学習なしで測れる）、上位10%を
取り直した。

| 条件 | `ret_o1_20` | `ret_o1_40` | 最悪の窓(40) | 日内AUC |
|---|---|---|---|---|
| 個々の引き（平均） | +0.80pt | +0.75pt | | |
| **4本を平均** | +0.96pt | **+0.72pt** | **−9.28pt** | **0.6076** |
| A 旧データ・旧パラメータ | +1.20pt | +1.33pt | −2.45pt | 0.6045 |
| B 新データ・旧パラメータ | +1.28pt | +1.62pt | −0.77pt | 0.6013 |

`ret_o1_20` では個々の平均より +0.16pt 良くなったが、`ret_o1_40` では
改善ゼロ（+0.75 → +0.72pt）で、**最悪の窓はどの個別の引きより悪化した**
（−9.28pt）。スコアを平均しても、上位10%に選ばれる銘柄の集合は個々の
どれとも違うものになり、それが良い集合である保証はない。

日内AUC は全条件で最良（0.6076）だったのに実収益は改善していない。
ここでも AUC と実収益は一致しない。

## 運用への含意

事実として確定しているのは2つだけ。

- **週次の探索引き直しは、窓平均を 0.6〜1.5pt 動かす。**
  モデルの種のノイズ床（0.143pt）の4〜11倍で、データを直した効果
  （+0.08 / +0.29pt）よりはるかに大きい。
- **どのやり方が良いかは決着していない。** 分布は重なり、平均の差は
  z −0.94。足切り（z>2）を越えたものは1つも無い。

`.github/workflows/retrain-weekly.yml` のコメントは以前からこう書いていた
——「特徴量も母集団も変えていないのにパラメータが週ごとに動く。予測が
変わったときに『相場が変わった』のか『パラメータが変わった』のかを
切り分けられなくなる」。今回、その切り分けられなさが **実収益で
0.6〜1.5pt** という具体的な大きさで見えた。

**この測定だけでパラメータを固定してはいけない。** 「いちばん良く測れた
引きを選ぶ」は評価に使った同じデータで選ぶことになり、8本も測れば
最良の1本は偶然でも良く見える。手を入れるなら、選び方そのものを
（別の期間で）検証してからにする。
