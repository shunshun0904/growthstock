運用者の依頼（2026-10-10）: 「本番で稼働しているモデルの予測スコア（ダッシュボード）に加え、
売買判断には Jev による予測値を使いたい」。同日の運用者の決定（AskUserQuestion の4問）:

| 問い | 決定 |
|---|---|
| Jev に何を予測させるか | **「翌営業日の寄りで買い、20営業日以内に +10% に届く」の真偽の確率（noul）**。実験70 の物差し（+10% の指値）と同じ |
| Jev に渡す情報 | **候補の実測値 ＋ 4モデルの百分位と寄与**（モデルの読みを踏まえた審査。独立した意見にはしない） |

## 1. Jev とは

TypeSafe AI（2024年創業、サンフランシスコ）が **2026-09-15** に公開した「System One」と呼ぶ判断特化のモデル。
LLM と違って文章を生成せず、与えた状態（テキストか JSON）と名前付きの問いに対して、**型付きの値と確率だけ**を返す。
問いは3種類:

| 種類 | 返るもの | 用途 |
|---|---|---|
| `noul` | 真偽の確率（0〜1） | 「この文は正しいか」。ここで使う |
| `choice` | 選択肢ごとの確率と選ばれた1つ、確信度 | 分類・振り分け |
| `score` | 段階の期待値と段階ごとの確率、確信度 | 採点 |

公式: [typesafe.ai](https://typesafe.ai/) / [docs.typesafe.ai](https://docs.typesafe.ai/)（Quick start・
[HTTP API](https://docs.typesafe.ai/api)・[primitives](https://docs.typesafe.ai/primitives)）/
[Python SDK](https://github.com/typesafe-ai/typesafe-sdk-python)（`typesafe-sdk`、Python 3.10+）/
[JavaScript SDK](https://github.com/typesafe-ai/typesafe-sdk-js)。OpenRouter・Cloudflare・Vercel の
ゲートウェイ経由でも使える。日本語の解説は Zenn・Qiita・GMO の記事がある（2026-09-18 以降）。

**金融での実績は無い。** 株価の向きを当てる目的で作られたモデルではなく、公開の検証も
「社内の判断を速く安く」の類が中心。コミュニティの検証（[awesome-typesafe-jev](https://github.com/AbdelStark/awesome-typesafe-jev)
に一覧）では、確率は**較正されていない**（「0.52」が 52% の正解率を意味しない）と繰り返し指摘されている。
株に当てた例は [sosopop/jev_stock](https://github.com/sosopop/jev_stock)（香港株の短期の方向。4銘柄×30件で
正解率 45%、作者自身が「検証済みの定量モデルではない」と注記）など、実験の段階のものだけ。
ここでも**「Jev がそう言った」以上の意味を、測るまで与えない**。

## 2. 何をどう問うか（`research/jev_predict.py`）

### 問い（`QUESTIONS`、版 `rise10_v1`）

```
type: noul
instructions: この日本株を翌営業日の寄り付き（始値）で買ったとき、買った日を1日目として
              20営業日以内に、株価の高値が買値の +10% 以上に達する。
criteria.true:  20営業日以内のいずれかの日の高値が、買値の 1.10倍以上になる
criteria.false: 20営業日のあいだ、高値が一度も買値の 1.10倍に届かない
```

「買った日を1日目」「高値で判定」は実験32・70 の `hit10`（`research/exp/e32_takeprofit.py`）と同じ定義。
運用の出口（+20% の指値・20営業日）ではなく +10% にしたのは、+20% の到達が約1割しか無く、確率を問うても
ほぼ「届かない」になるため。実験70 の物差し（+10% の指値の収益）と揃えてある。
文言を変えたら `QUESTION_VERSION` を上げる（控えと予測ファイルに版が残り、違う版の答えを混ぜない）。

### 渡すもの（`build_state`。日本語の鍵の JSON）

| 塊 | 中身 |
|---|---|
| 課題・日付・銘柄 | 何を判定するか。日付。コード・名前・業種・市場・規模区分 |
| 株価 | 終値・78週高値・高値に対する位置・抜けた幅・ベースの長さ・20日リターン・日次ボラ・出来高トレンド |
| 需給・規模 | 時価総額・売買代金20日平均・信用倍率 |
| バリュエーション | PER・PBR・配当利回り |
| 決算 | EPS 成長率・売上成長率・ROE・営業利益率・進捗率と基準・四半期 |
| その日 | 発火数・基準モデルでの順位・地合い（候補全体の地合い寄与の中央値。画面と同じ ±0.05） |
| 機械学習モデルの見立て | LightGBM / XGBoost / CatBoost / ロジスティック回帰 の百分位、必要上昇率。母集団の正例率が約18%という説明 |
| 基準モデルの寄与 | TreeSHAP の区分ごとの寄与と、効いた特徴量の上位8つ（列名・意味・寄与） |

画面に出している値（`predictions.json` の候補）をそのまま使う。**欠測は書かない**（0 で埋めると「実測でゼロ」と混ざる）。
1件あたり 1,500〜2,000文字（公開中の予測ファイルで `python3 research/jev_predict.py --dry-run` が出す）。
較正確率と帯の正例率は入れていない（百分位の単調な写しなので重複。実験73 でも前の窓だけから作り直せないため）。

### 呼び方

HTTP の形は公式 Python SDK（`typesafe-sdk` 0.7.4 の `_schemas/models.py`。`api.typesafe.ai/openapi.json` から
生成されたもの）から写した:

```
POST https://api.typesafe.ai/v1/systemone
Authorization: Bearer <TYPESAFE_API_KEY>
{"state": {...}, "model": "jev-latest", "questions": {"rise10": {"type": "noul", ...}}}
→ {"model": "jev-1.13.0", "answers": {"rise10": {"type": "noul", "noul": 0.37}},
   "usage": {"input_tokens": 900, "output_tokens": 1}}
```

SDK は入れず標準ライブラリ（urllib）で呼ぶ（依存を増やさず、通信を差し替えて単体テストするため）。
429 / 5xx / 接続失敗は 2・4・8秒で3回まで再試行（`retry-after` があればそれを優先）。400 系はすぐ止める。
鍵は環境変数 `TYPESAFE_API_KEY` からだけ読み、ログ・例外・repr に出さない。
モデル名は既定 `jev-latest`（別名）。応答に入る実際の版（例 `jev-1.13.0`）を答えごとに控える。
固定したいときは環境変数 `JEV_MODEL`。

### 原則

1. **鍵が無ければ何もしない。** 日次予測はそのまま動き、画面の Jev の列は出ない
2. **答えは (予測日, 銘柄コード, 問いの版) ごとに最初の答えで凍結する。** 控えは `research/_data/jev_answers.parquet`
   （Release `data-raw`。`predict.yml` が毎晩上げ、翌晩の Download raw data で戻る）。同じ日を予測し直しても
   問い直さず、課金もしない。記録（`prediction_history.json` / 台帳）と同じ考え方
3. **1銘柄の失敗で他を止めない。** 失敗は空のまま（0 で埋めない）。3回続けて失敗したら、その実行では残りを問わない
   （障害の日に予測ジョブを何十分も待たせない）
4. 1回の実行で問う数に上限（`JEV_MAX_PER_RUN`、既定 200）。新しい日・上位から順に問う。初回は画面の5営業日ぶん
   （40〜60件）、以後は1日十数件
5. **選定の規則には入れない**（`src/lib/strategy.js` の `strategySignal` は Jev を読まない。`tests/strategy.test.js` が固定）

## 4. 設定

1. TypeSafe AI の[コンソール](https://console.typesafe.ai/)で API キーを発行する
2. GitHub の `Settings → Secrets and variables → Actions` に **`TYPESAFE_API_KEY`** として登録する
3. 次の夜の `Predict Breakouts` から Jev の列が入る（過去分は遡らない。実験73 で測る）。
   先に確かめるなら、Actions の `Run Experiment` で `exp=e73_jev_oof.py args=--dry-run`（通信しない）か、
   手元で `TYPESAFE_API_KEY=... python3 research/jev_predict.py --check`（GET /v1/models）・`--sample`（1件だけ問う。課金あり）

費用は入力トークン課金（出力は無料と OpenAPI の説明にある）。1件 1,500〜2,000文字なので、毎晩十数件なら
月に数十万トークン。単価は公式の料金表を見る（このセッションからは読めなかった）。

## 5. 実験73（`research/exp/e73_jev_oof.py`）: 直近1年の OOF 候補に当てる

先に決めたこと（結果を見てから分け方を足さない。スクリプトの冒頭に同じ文）:

- **対象**: 本番の OOF（lgbm / xgb / cat / logit）の行のうち、最新日から 365暦日以内で、全モデルの百分位
  （その行より前の窓の分布。実験70 と同じ基準）と +10% の結果が付く行（約3,000件の見込み）
- **state**: 本番と同じ作り。寄与は**その行の窓の** LightGBM（本番のパラメータで窓ごとに学習し直す）の TreeSHAP。
  本番の学習済みモデルの SHAP を使うと、その行を学習に使った in-sample の寄与（ラベルを少し知っている）を
  Jev に渡してしまうため
- **腕**: `prod`（本番と同じ。銘柄名・コード・業種・市場・日付を含む）と `anon`（それらを伏せる）。Jev は 2026-09-15 公開の
  モデルで、過去の日付の銘柄については「その後どうなったか」を学習データから知っている疑いがある。anon との差が
  その大きさの目安。**差が無ければ先読みの心配は小さい。prod だけ良ければ prod の数字は当てにならない**
- **見るもの**: (1) 較正（10pt 刻みの帯ごとの実際の到達率。Brier を「母集団の到達率を常に答える」基準と比べる）
  (2) 分離力（hit10 の ROC-AUC。各モデルの百分位・3モデルの最小と比べる。日付内の AUC も）
  (3) 運用との重なり（線の上・際どい候補・母集団を Jev 50 以上/未満で分ける。差と SE・z。SE は銘柄ごとにまとめる）
  (4) 相関（Spearman。prod と anon も）(5) 費用
- **記録**: 集計だけをログに出す（銘柄ごとの値は出さない。2026-10-10 の決め事）。答えは `research/_data/oof/e73_jev_answers.parquet`
  に控え、Actions のキャッシュに乗る（公開の成果物には上げない）。途中で止まっても続きから

回し方: Actions の `Run Experiment` で ref `claude/jquants-browser-app-bwk19a`（マージ後）、`exp=e73_jev_oof.py`。
`args=--dry-run` で件数・文字数・state の例（anon）だけ。`args="--arms prod --limit 200"` で費用の確かめ。
既定は両腕・直近1年。鍵は `run-experiment.yml` が Secrets から渡す。

**採否の決め方（先に書く）**: Jev を選定の規則に入れるかは、実験73 の「線の上を Jev 50 で分けた差」が
`docs/MODEL_ADOPTION_RULES.md` §7 の精神（対照と区別でき、向きが一貫）で見えること、**かつ** anon でも同じ向きであること、
**かつ** 前向きの記録（2026-11 の集計以降）でも向きが同じこと、の3つがそろってから。1つの実験で決めない
（運用者の方針「1つの OOF で戦略を決めると過適合する」）。

### 結果（2026-10-10、run 38078175856。本番の239列の OOF、2025-09-01〜2026-09-01 の 3,830件・2,094銘柄）

回し方: dry-run（run 38077427648）→ prod 200件（run 38077799335、鍵の疎通とトークン数の確かめ）→ 全体。
Release の OOF に残っていた優先株（25935）の1行は、いまのデータセットに無いので外した。答えたモデルは全件
`jev-1.13.0`（別名 `jev-latest`）。失敗 0。

**結論を先に。Jev の「+10% 到達」の確率は、+10% に届くかは分ける（ROC-AUC 0.62）が、+10% の指値で売ったときの
収益では差を作らない。確率の値は較正されていない（70〜90% と答えた帯の実際の到達率は 44〜45%）。線の上・際どい
候補の中では Jev が高い側のほうが収益が低かった（有意ではない）。選定の規則には入れない（運用者の決定どおり）。
画面と台帳には参考値として残し、前向きの記録を続ける。** 先読みの疑い（prod と anon の差）は小さかった。

対象の母集団: +10% 到達率 36.1% / +10%指値 +1.21% / 持ち切り +1.62%。

#### 1. 較正

| 腕 | Brier（Jev） | Brier（母集団の到達率 36.1% を常に答える基準） |

| prod | 0.2762 | 0.2306 |
| anon | 0.2696 | 0.2306 |

答えた数字の6割弱**。+10%指値の収益は帯で並ばない（+0.70〜+1.64% の間で上下）。anon も同じ形（20〜30: 21.4%、
30〜40: 26.7%、40〜50: 37.2%、60〜70: 49.5%、70〜80: 43.9%、80〜90: 44.6%）。

#### 2. 分離力（ROC-AUC。「日付内」はその日の候補の中での順位、230日）

| 並べる物差し | +10% 到達（hit10） | モデルの正例（+1.2σ） | 日付内（hit10） |
|---|---:|---:|---:|
| Jev（prod） | **0.617** | 0.475 | 0.611 |
| Jev（anon） | 0.607 | 0.479 | 0.605 |
| LightGBM の百分位 | 0.480 | **0.602** | 0.476 |
| XGBoost の百分位 | 0.473 | 0.586 | 0.471 |
| CatBoost の百分位 | 0.460 | 0.580 | 0.455 |
| ロジスティック回帰の百分位 | 0.457 | 0.599 | 0.445 |
| 3モデルの最小 | 0.471 | 0.589 | 0.468 |

**Jev と4モデルは別のものを当てている。** Jev は「+10% に届くか」（固定の幅）を分けるが、モデルの正例（銘柄の
ボラで正規化した +1.2σ）は分けない（0.48）。4モデルは逆で、正例は分けるが固定の +10% は分けない（0.46〜0.48。
0.5 を下回る＝百分位が高いほど +10% には届きにくい）。固定の +10% は荒い銘柄ほど届きやすく、モデルは静かな
高値更新を高く見るので、この向きの違いは物差しの違いから出る。素朴な基準（日次ボラそのもの）との比較は
run 38078175856 のあとに足した（下の「追記」）。

#### 3. 運用との重なり（Jev 50% 以上 / 未満。+10%指値の収益）

| 腕 | 範囲 | Jev | 件数 | +10%指値 | SE | 持ち切り | 勝率 | +10%到達 | −10%割れ |
|---|---|---|---:|---:|---:|---:|---:|---:|---:|
| prod | 線の上（3つとも95以上） | ≥50 | 7 | （少なすぎる） | | | | | |
| prod | 線の上 | <50 | 20 | +3.17% | 1.36 | +2.60% | 70% | 35% | 0.0% |
| prod | 際どい候補（実験70 の形） | ≥50 | 71 | +0.73% | 1.29 | +3.59% | 52% | 48% | 14.1% |
| prod | 際どい候補 | <50 | 96 | +3.21% | 0.75 | +4.20% | 67% | 39% | 5.2% |
| prod | 母集団 | ≥50 | 1,933 | +1.27% | 0.23 | +1.92% | 59% | 45% | 17.4% |
| prod | 母集団 | <50 | 1,897 | +1.15% | 0.17 | +1.30% | 55% | 27% | 7.0% |

差（Jev≥50 − Jev<50、+10%指値）: 線の上 −5.45pt ± 6.04（z −0.90。7件対20件）/ 際どい候補 **−2.48pt ± 1.50
（z −1.66）** / 母集団 +0.12pt ± 0.28（z +0.43）。anon も同じ向き（−3.56 ± 5.50 / −2.13 ± 1.47 / +0.16 ± 0.28）。

**Jev が高い側は、+10% には多く届く（45% 対 27%）が、−10% 割れも多い（17% 対 7%）。** 母集団では +10%指値の
平均は同じ。運用で実際に見る範囲（線の上・際どい候補）では Jev が高い側のほうが悪いが、件数が少なく有意ではない。
**「Jev が高いから買う」「低いから見送る」のどちらにも根拠は無い。**

#### 4. 相関（Spearman）

+20%指値 +2.28% 対 +1.31% と差があるが、これは母集団の C の AUC 0.57 と同じ情報で、モデルが選んだ中では消える。

prod と anon の相関: A 0.921 / B 0.953 / C 0.940 / R 0.918。平均の差は A +2.2pt、他は ±1pt 以内。先読みの疑いは小さい。

#### 読み方と決めたこと

- **採用しない。** 採否の条件の1つ目（正例を物差しに、3モデル90以上の中で 真陽性 − 偽陽性 の差が正で |z| ≥ 2）を、
  4問のどれも満たさない。差は全部 0 以下で、向きは実験73 と同じ（答えが高いほど悪い）
- 問いの言い方を「届くか」「儲かるか」に変えても、数字だけを渡す限り Jev は渡した数字（20日リターン・日次ボラ）を
  読み返す。C（正例の定義そのものを問う）だけはモデルに近い答えを返すが、モデルより弱く、モデルの選んだ中では
  何も足さない
- 母集団で見える「C が高いほど正例率が高い（25% 対 20%）」は、モデルの百分位で選ぶことで既に取り込まれている。
  画面で Jev を見る理由は、いまのところ無い
- 本番の問い（R = rise10_v1）は変えない。変える根拠が無いため。前向きの記録は、マージするなら参考値として続く
- 次に試す価値があるのは、問いではなく**渡すもの**を変える案（モデルが持っていない文字情報: 適時開示の本文・
  決算短信の文章・会社の事業の説明など）。ただし過去1年の候補ぶんの文字情報を集める取り込みが要るので、別の設計
  （費用と期間の見積り）を先に書く

## 8. 実験75（`research/exp/e75_lowvol_pick.py`）: Jev を使わず、日次ボラで同日の選び方を比べる

運用者の読み（2026-10-11、実験74 の結果を見て）: 「Jev の確率は 20日リターンと日次ボラの言い換えに近いので、母集団では
『荒い銘柄は +10% の高値を付けやすい』という形で Precision と相関する。3モデル95以上で買う候補でも、Jev が異様に高ければ
ボラが大きいので逆に振れるリスクがある。同日に 95 以上とまではいかなくても Jev が低めの銘柄があれば、そちらを選ぶ使い方は
あり得る」。

実験74 の数字で確かめると、向きは合っている。3モデルとも90以上の 115件の中で正例を分ける ROC-AUC は、日次ボラ1列 0.312
（低いほど当たる。反転で 0.69）、20日リターン 0.401、Jev R 0.367、Jev C 0.489。+20% 指値の収益の符号でも日次ボラ 0.346 で
Jev（0.343〜0.424）と同等以上。ただし Jev は 20日リターンの言い換え（相関 0.78〜0.92）が主で、日次ボラとの相関は 0.44〜0.55 に
とどまる。**この使い方をするなら、Jev ではなく Jev に渡している日次ボラ（`vol_20d`）そのもので測る。** 費用ゼロ・決定的・Jev の
モデル版に依らず・全期間の OOF で検証できる（Jev は直近1年しか測っていない）。

注意: モデルの正例は「ボラの 1.2σ 以上の上昇」なので、低ボラほど必要な上昇が小さく、正例になりやすいのは定義上の帰結を含む。
採否は正例率ではなく、実際の収益（+20% 指値の平均）で見る。低ボラ銘柄は +20% に届く回数が減る一方、届かなかったときの損が
小さくなるので、符号だけでなく平均の大きさを測る。

運用者の決定（2026-10-11、AskUserQuestion）: 規則は「3モデル90以上の中で日次ボラが最も低い1銘柄」と「3モデル95以上を優先し、
無い日は 90以上の低ボラ1銘柄」。基準はいまの規則（3モデル95以上を全部、3モデル90以上を全部）。主の物差しは +20% 指値の収益の
平均。直近1年は実験74 の控え（Jev の答え）も並べる。API の課金なし。

先に決めたこと（スクリプトの冒頭と同じ。結果を見てから分け方を足さない）:

- **対象**: 本番の OOF（lgbm / xgb / cat）の全期間で、3モデルの百分位（前の窓の分布。実験70 と同じ）と +20% の結果が付く行。
  その日の候補 = 3モデルとも90以上の行（画面の線）
- **規則**（1日ごとに選ぶ。候補が無い日は買わない）

| 名前 | 種類 | 選び方 |
|---|---|---|
| `all95` | 基準 | 3モデルとも95以上を全部買う（運用者の線） |
| `all90` | 基準 | 3モデルとも90以上を全部買う（画面の線） |
| `top1` | 基準 | 90以上の中で 3モデルの最小が最大の1銘柄（画面の並び順。同点は LightGBM のスコア） |
| `top2` | 基準 | 同じく上位2銘柄（`STRATEGY.topK` = 2） |
| `lowvol1` | 規則 | 90以上の中で日次ボラが最も低い1銘柄（同点は 3モデルの最小が高いほう） |
| `pref95` | 規則 | 95以上がある日はその中の `top1`、無い日は 90以上の `lowvol1` |
| `lowvol2` | 参考 | 90以上の中で日次ボラが低い2銘柄 |
| `lowvol95` | 参考 | 95以上がある日はその中の低ボラ1銘柄、無い日は 90以上の `lowvol1` |
| `lowjev1` | 参考 | 90以上の中で Jev（R: +10% 到達の確率、prod 腕）が最も低い1銘柄。実験74 の控えがある直近1年だけ |

- **物差し**: 主 = +20% 指値の収益（`tp20`。20営業日以内に届けば +20%、届かなければ持ち切り）の1件あたり平均。
  副 = +10% 指値、持ち切り、勝率（tp20 > 0）、+20% 到達率、正例率、−10% 割れ（持ち切りが −10% 未満）の率
- **SE**: 1件あたり平均の SE は銘柄と日付の2方向でまとめる（CR1。V = V_銘柄 + V_日付 − V_iid）。規則同士の差は**同じ日の対**で
  取る（その日に規則A が選んだ行の tp20 の平均 − 規則B の同じもの。両方が選んだ日だけ。同じ銘柄を選んだ日は差 0 として数に
  入れる）。SE は月でまとめる（20営業日の保有が重なる隣の日の相関を吸う）。違う銘柄を選んだ日だけの差と、年ごとの差の符号も出す
- **見るもの**: (1) 規則ごとの成績 (2) 規則同士の差（`lowvol1 − top1`、`pref95 − top1`、`lowvol95 − top1`、`lowvol2 − top2`、
  `lowvol1 − all90`、`pref95 − all95`）(3) 発火数 8 未満の日を見送ったとき（運用の見送り線）(4) 選定の集合の中で並べる物差し
  （日次ボラ・20日リターン・3モデルの最小・LightGBM の百分位の、正例と tp20>0 の ROC-AUC と 真陽性−偽陽性 の差、日次ボラの
  3分位）(5) 直近1年の窓で Jev・日次ボラ・20日リターンを同じ土俵に（`top1` / `lowvol1` / `lowjev1` / `pref95` と、
  `lowvol1 − lowjev1` などの対）(6) 採否の条件の確認
- **採否を検討する条件（全部そろったとき。1つの OOF で決めない。満たしても前向きの記録で確かめてから選定の規則に入れる）**:
  (1) `lowvol1` または `pref95` の tp20 の平均が `top1` より高く、同じ日の対の差（月まとめ SE）で z ≥ 2
  (2) その差が年ごとに過半の年で正 (3) −10% 割れの率が `top1` より高くない
  (4) 直近1年の窓で、その規則の tp20 の平均が `lowjev1` より低くない（Jev を使う理由が無いことの確認）
- **記録**: 集計だけをログに出す（銘柄ごとの値は出さない）

回し方: Actions の `Run Experiment` で ref `ccr-8db003a2-emjac6`、`exp=e75_lowvol_pick.py`、**`reuse=e74_jev_questions.py`**
（実験74 のキャッシュ＝Jev の控え `e74_jev_answers.parquet` と値動きの表を先に戻す。`run-experiment.yml` に足した入力。キャッシュの
キーは実験名ごとなので、これが無いと他の実験の途中結果は見えない）。`args=--dry-run` で件数と規則ごとの件数だけ。鍵は要らない。
`reuse` を省くと §5（Jev との比較）だけ飛ばして動く。
