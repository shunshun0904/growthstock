# 価格帯別需給の銘柄別配信

2026-11-15現在、本番運用に用いる推定精度として十分ではないとの運用者判断により、タブは非表示です。
画面・推計処理・データ配信は残しています。以下は機能の仕様で、表示の切り替えは`src/App.jsx`の`hidden`で行います。

日次の詳細取得対象から外れた保存済み銘柄も、需給データを表示します。
ブラウザの保存銘柄をサーバーへ送信する必要はありません。
取得済みの日次株価と、公表日・約定金額付き信用残から、取得対象を予測候補に限定せず表示用データを生成します。

## 生成と更新

GitHub Pagesのビルドで`scripts/build_supply_demand_assets.sh`を実行します。
既存の`data-raw` Releaseにある最新2年分の株価を使い、J-Quantsの直近10営業日分の信用残を取得します。
公表日は株価基準日以前のものだけを利用します。直近に約定がない銘柄や、直近の一覧から外れた過去の銘柄は、その株価日までの信用残履歴を別途確認します。
2026-09-25より前の週次残は既存の年別キャッシュも利用し、公表日は従来の取引カレンダーに基づく推定として表示します。以降の公表日不明な行を、利用可能だったと仮定して補完することはしません。
年初の休場日にも、存在する最新の年別ファイルを選ぶため、まだ生成されていない年のファイルを要求しません。

- `dist/data/supply-demand/index.json`：対象コード・状態・株価基準日の一覧。
- `dist/data/supply-demand/<5桁コード>.json`：その銘柄の信用残・平均建値・60/120/250営業日の推定分布。

数千件のJSONをGitへ日次コミットせず、Pages成果物へ直接生成します。
データを全部生成し終えてから公開先ディレクトリへ移すため、生成途中の一覧は公開しません。
各回の生成時点にある入力を使い、入力のない株価・信用残を0で補いません。

既存のRepository Secret `JQUANTS_API`をActions内だけで使います。
ブラウザは公開JSONを読むだけで、APIキー・モデル・秘密の計算処理を受け取りません。
新しいサービス・契約変更・キー発行は不要です。

API障害等で生成できない場合も、既存の銘柄詳細データとサイト公開を維持します。
画面には追加の配信データを取得できなかったことを示し、明示的に再試行できます。
選択一覧に銘柄が残ることと、その銘柄の株価・信用残の公表データが揃うことは区別します。

## 画面

最初に一覧JSONを確認し、選択した銘柄のファイルだけを読み込みます。
4桁コード・英字入りコード・自己株式等の別種株券コードは5桁へ正規化して照合します。
銘柄変更中の古い応答を新しい銘柄のデータとして表示しません。
正常応答は画面内で再利用し、エラーは自動で繰り返さず「需給データを再試行」で取り直します。
一覧には「信用残データなし」「株価データなし」「分割調整を確認できず」などの理由を表示します。

## 計算

既存の`build_supply_demand`を利用します。出来高・VWAPに基づく分布と、公表金額がある場合の平均合わせは従来どおりです。
回転率の減衰係数を使った研究モデルには切り替えていません。
信用残の基準日・公表日・株式分割の調整を引き継ぎます。
株数・平均建値の保存則を保ったまま全銘柄へ展開するため、正規化の和を一度だけ計算する等価な高速化を加えています。
分類・ランキングのモデル、学習データ、推論、予測結果は変更しません。
