# 新高値ブレイクアウト予測モデル 設計

## 0. この文書の位置づけ

「過去3決算の8軸系列を特徴量として、1〜6ヶ月先に新高値ブレイクが起きるかを予測する」
モデルの設計。**実装前に方法論の穴を潰しておく**ことを目的とする。

株価予測は、素朴に組むとほぼ確実に「動いているように見えるが実際には使えない」モデルになる。
主な原因は リーク / 生存バイアス / 不適切な分割 / 不適切な評価指標 の4つで、
本設計はそれぞれに対する具体的な対処を明記する。

---

## 1. 実測したデータの前提

`research/probe_*.py` を J-Quants API V2 に対して実行して得た**実測値**（推測ではない）。

| 項目 | 実測値 | 設計への影響 |
| --- | --- | --- |
| 上場銘柄数 | 4,441社 | 母集団として十分 |
| 日付一括取得 | 1リクエストで全4,441行 | 銘柄ループ不要。全期間の構築が現実的 |
| 株価の遡及 | **2016年10月〜**（それ以前は契約範囲外） | 学習期間は約10年 |
| 全銘柄1日分の取得時間 | **4.19秒** | 全期間2,432営業日で約170分 |
| 財務の日付指定 | 可（決算期は2週間で3,057件） | 開示日ベースで point-in-time に組める |
| 信用残の遡及 | 2018年〜（51週/年） | 需給軸も概ね全期間で使える |

2016年以前は API が明示的に `Your subscription covers the following dates: ...` を返す。
契約プランのカバー範囲であり、実装で回避できるものではない。

**10年という期間の意味**: 2018年の調整、2020年のコロナ・ショック、2021年の上昇、
2022年の金利上昇局面、2023年以降の日本株上昇 と、性質の異なる複数の相場局面を含む。
単一局面で学習した「たまたま地合いが良かっただけ」のモデルを避けられる。

### 生データの保存と差分取得

全期間の取得は約2.5時間かかる（実測。1年シャードあたり約50分 × 10年を4並列）。
定義を変えるたびに取り直すのは現実的でないため、生データを保存して
**まだ取得していない営業日だけ**を取りに行く。

| | 保存なし | 保存 + 差分取得 |
| --- | --- | --- |
| 初回 | 2.5時間 | 2.5時間 |
| 日次更新 | 2.5時間 | **約5秒**（1営業日ぶん） |
| ラベル定義の再検証 | 2.5時間 | **0秒**（取得不要） |

**保存先**: GitHub Release（タグ `data-raw`）。年別 parquet + `manifest.json`。
外部の認証情報が不要（`GITHUB_TOKEN` のみ）で永続する。全期間で約242MB
（1年あたり24MB・実測）なので、1アセット2GBの上限に対して十分収まる。

**差分判定**: `manifest.json` に「その日を取得しに行ったか」を記録する。
行数で判定してはいけない — 財務はその日の開示が0件の日が普通にあり、
行数で見ると毎回叩き直すことになる。

**年別に分ける理由**: 更新時に書き換えるファイルを最小限にするため。
日次更新なら当年のファイルだけを触れば済み、過去年は再アップロードが要らない。

### 取得の実行計画

全期間を1ジョブで回すと約3時間かかり、失敗時のやり直しコストが大きい。
**年ごとにシャーディングして並列実行**する（1シャード約17分）。

さらに、いきなり10年分を流さず **まず1年分でパイプライン全体を検証**してから
全期間に広げる。特徴量表の形・正例率・欠測率を先に確認するため。

## 2. 予測対象（ラベル）の定義

### 2.0 定義は比較して決める

初回のパイロット（2023-2024年）でチャートを目視した結果、
「高値を一時的に超えたが、その後失速した」ケースが正例に混ざっていた。
現行定義は「ブレイク後20営業日、-8%を割らない」しか見ておらず、
**その先の失速を許容している**ためである。

そこで定義を1つに決め打ちせず、`research/compare_label_defs.py` で
同一データ上の実測を並べて選ぶ。変更軸は3つ。

| 軸 | 選択肢 | ねらい |
| --- | --- | --- |
| 高値窓 | 52週 (245日) / **78週 (368日)** | 超えるべき水準を上げ、浅い高値更新を除く |
| ホライズン | 1〜6ヶ月 (t+20〜120) / **1〜3ヶ月 (t+20〜60)** | 予測期間を絞る |
| 定着 | hold 20日 / **40日**、**+ 水準維持** | 失速したケースを正例から外す |

**定着条件の2案**

* `hold_days`: ブレイク後 N 営業日、終値がブレイク時終値の `hold_drawdown` を割らない
  （= **急落しないこと**を見る。期間を 20→40 に延ばすと、より長く粘ることを要求する）
* `sustain_days` / `sustain_ratio`: ブレイク N 営業日後の終値が、
  ブレイク時終値の `sustain_ratio` 倍以上
  （= **一定期間後も水準を保っていること**を見る。じりじり戻して失速するケースを直接除ける）

前者は「下に急落しないか」、後者は「上げた水準に留まっているか」を見ており、
性質が違うため両方を比較対象に入れる。

### 2.1 ブレイクアウトの定義

基準日 $t$ から見て、$[t+20\text{営業日},\ t+120\text{営業日}]$（約1〜6ヶ月）の間に
以下を**すべて**満たす日 $b$ が存在すれば正例（$y=1$）とする。

1. **高値更新**: $\text{Close}_b > \max(\text{High}_{b-245 \ldots b-1})$
   （終値が過去52週の最高値を上抜け）
2. **出来高の裏付け**: $\text{Volume}_b \geq 1.5 \times \overline{\text{Volume}}_{b-20 \ldots b-1}$
3. **定着**: $\min(\text{Close}_{b+1 \ldots b+H}) \geq 0.92 \times \text{Close}_b$
   （ブレイク後 $H$ 営業日、ブレイク時終値から-8%を割り込まない）
4. **水準維持**（任意）: $\text{Close}_{b+S} \geq r \times \text{Close}_b$
   （ブレイク $S$ 営業日後も、ブレイク時終値の $r$ 倍以上）

条件2が「だまし」の多くを、条件3が「吹き上げて即失速」を除外する。
条件3は $b+20$ 営業日まで見るため、ラベル確定には基準日から最大140営業日を要する。

### 2.2 除外条件（基準日 $t$ 時点で適用）

| 除外 | 理由 |
| --- | --- |
| $R_{high}(t) \geq 95\%$ | すでに高値圏。「これからブレイクするか」の問いとして自明に近い |
| 上場から245営業日未満 | 52週高値が定義できない |
| 売買代金の20日平均 < 0.5億円 | 実際には売買できない。ノイズにしかならない |
| $t+140$ 営業日のデータが無い | ラベルを確定できない（**未確定を正例/負例に混ぜない**） |

### 2.3 サンプリング

各銘柄について**月次**（各月末営業日）に1サンプル。日次で取ると
隣接サンプルがほぼ同一になり、実質的な独立サンプル数を大きく水増ししてしまう。

## 3. 特徴量

### 3.1 決算系（過去3決算 × 4軸 = 12）

基準日 $t$ **までに開示済み**の直近3決算から、各決算時点の値を取る。

| 軸 | 指標 |
| --- | --- |
| EPS成長 | 単一四半期EPSの前年同期比 |
| 売上成長 | 単一四半期売上高の前年同期比 |
| 収益質 | ROE |
| 利益率 | 営業利益率 |

決算データは会計年度内の累計で提供されるため、
既存の `quarterize()` で単一四半期に差分展開してから前年同期と比較する。

### 3.2 決算系の変化（4軸 × 3 = 12）

CANSLIM の核心は水準そのものより**加速**なので、以下を明示的に与える。

- 直近 − 3期前（変化幅）
- 直近 − 前期（直近の変化）
- 3期の線形回帰の傾き（トレンド）

### 3.3 株価・需給系（基準日 $t$ 時点、8）

| 特徴量 | 備考 |
| --- | --- |
| 52週高値接近率 $R_{high}$ | 最重要のベースライン特徴量 |
| $R_{high}$ の3ヶ月前・6ヶ月前の値 | ベースを固めつつあるか |
| 出来高モメンタム | 20日平均比 |
| 売買代金（対数） | 流動性 |
| 時価総額（対数） | サイズ効果 |
| 信用倍率 | 需給 |
| 決算進捗率 − 経過基準 | 進捗の上振れ度 |

### 3.4 市場環境（2）

同時点の TOPIX の 20日 / 120日リターン。
**「市場全体が上がっていたから」を、銘柄固有の力と分離する**ために必須。
これが無いと、モデルは実質的に相場局面を暗記する。

合計 **約34特徴量**。

## 4. 検証設計（ここが最も重要）

### 4.1 リーク対策

| リスク | 対処 |
| --- | --- |
| 決算の先読み | `DiscDate`（開示日）で厳密に切る。決算期末日では切らない |
| 未来のバーの参照 | 特徴量は $t$ 以前のバーのみで算出（既存の point-in-time 実装を流用） |
| ラベル期間の重複 | 訓練の最終日と検証の開始日の間に **140営業日のエンバーゴ**を置く |
| 生存バイアス | 上場廃止銘柄を除外しない。基準日時点で上場していた銘柄をすべて含める |

### 4.2 分割

ランダム分割は使わない（時系列かつ同一日の銘柄間が強く相関するため）。

```
|--------- 訓練 ---------|--エンバーゴ--|--- 検証 ---|--エンバーゴ--|--- テスト ---|
  2018-04 〜 2023-12        140営業日     2024 〜 2025    140営業日     2025 〜 直近
```

テスト期間は**最後に一度だけ**評価する。

### 4.3 評価指標

正例は少数（見込み5〜15%）なので **Accuracy は使わない**（全部「起きない」と答えても90%になる）。

- **PR-AUC**（主指標）
- **Precision@k**: スコア上位k銘柄の的中率。実運用に最も近い
- **リフト**: 上位k%の正例率 ÷ 全体の正例率

### 4.4 ベースライン（これに勝てなければ意味がない）

| ベースライン | 内容 |
| --- | --- |
| 全部「起きない」 | 下限 |
| $R_{high}$ 単独 | 高値に近いほど高スコア。**これに勝てなければ34特徴量は無駄** |
| 既存の8軸総合スコア | 現ダッシュボードのスコアに予測力があるかの検証も兼ねる |

## 5. モデル

- **主モデル**: 勾配ブースティング（scikit-learn `HistGradientBoostingClassifier`）
  - 表形式・数万〜数十万サンプル・欠測ありの条件に最も素直に合う
  - 欠測を欠測のまま扱える（本パイプラインは欠測を 0 で埋めない方針なので相性が良い）
- **解釈用**: ロジスティック回帰（標準化 + 欠測は中央値補完）
- 深層学習は**採用しない**。この規模・この特徴量数で勾配ブースティングを上回る根拠がない

不均衡への対処は `class_weight` 相当（サンプル重み）で行い、
閾値は検証データ上で Precision@k を見て決める。

---

## 6. 想定される結果について

事前に述べておくべきこと。

- 株価の方向性予測でPR-AUCが劇的に高く出た場合、**まずリークを疑うべき**
- 現実的な期待値は「$R_{high}$ 単独のベースラインを有意に上回る」程度
- 上回らなかった場合、それは失敗ではなく**「この特徴量セットには追加の予測力が無い」という結論**として報告する

数字が出なかったときに定義を後から緩めて見栄えを良くすることはしない。
