## 1. いまの前処理と、線形・MLP にとっての問題

`tuning_multi.preprocess`: カテゴリ4列は最頻値補完 → one-hot（34+18+6+8 = 66 列）。数値235列は中央値補完 → 欠損指示子 → 標準化。すべて ColumnTransformer の中なので fold の訓練側だけで決まる。

問題は3つ。

1. **裾の重い列を切らずに標準化している。** 例（99%点 / 尖度）: `xh_inc_cost` 7,083,000,000 / 1,224、`credit_ratio` 1,920 / 2,610、`xh_net` 3,564,870,000 / 526、`xh_dec_amt` 46,543,000,000 / 5,357、`eps_growth_q0` 2,591 / 6,323、`eps_growth_chg3` 2,205 / 952。EPS 成長率は前年の EPS が 0 近傍で発散する（EDA §5）。標準化の分母（標準偏差）がこの数行で膨らみ、残りの行が 0 付近に潰れる
2. **欠損の意味を分けていない。** 信用規制の3列（欠損 69% = 規制なし）、大量保有の比率（40〜67% = 報告なし）、政策保有の金額（31〜52%）、業績予想の修正幅（57% = 修正なし）を中央値で埋めると、「無い」行に「普通にある」行の値が入る。指示子で分けられるが、線形では指示子の重み1本で全列ぶんを打ち消すことになる
3. **完全に線形従属な列がある。** 決算8軸 × 変化6列（chg1 = q0−q1 など）は水準4列の線形結合。L1/L2 の正則化で数値的には問題ないが、ロジスティック回帰の係数の解釈はできない（効くかどうかの判断には影響しない）。|相関| ≥ 0.95 の組も11組ある（EDA §6）

変換の決め方（名前と意味で決め、データの統計は「裾が重いか」の判定にだけ使う）:

- 裾が重い: 99.9%点（または 0.1%点）が中央値から四分位範囲の20倍以上、または尖度 100 以上、または |z|>5 の行が 0.5% 以上、または最大 |z| が 15 以上。全データで判定して固定する（fold ごとに型が変わらないように）。有界の割合（52週高値比・自己資本比率・大株主の集中度など）と対数済みの規模は、裾が重く見えても切るだけ
- asinh(x / s): s = 訓練側の四分位範囲の半分。中央の半分はほぼそのまま、外は対数で縮む。符号を保つ
- log1p: 正の値だけ。0 は 0 のまま（「無い」を埋めた 0 がそのまま最小になる）
- 切る: 訓練側の分位点で clip。切った後に asinh / log1p / 標準化
- 「無い＝0」: 信用規制の比率、大量保有の比率、政策保有の件数・金額、業績予想の修正幅・上方修正の旗
- 「ずっと無い＝上限」: 修正からの日数（400）、上場からの年数（5）、規制・報告からの日数（訓練の最大）
- 指示子は全列で残す（いまと同じ。「無い」と「0 だった」を分けるのは指示子）

## 4. 線形・MLP に特有の注意

- ロジスティック回帰は `class_weight="balanced"`、MLP は重み付け無し（確率の水準は多数派に寄るが、運用は順位だけを使う）。前処理の案はどちらにも同じものを使う
- one-hot 66列 + 数値235列 + 指示子（欠損のある列ぶん）で入力は 400 列前後。MLP の層（16〜128）に対して入力が多いので、正則化（alpha）の探索幅はいまのまま広く取る
- 線形従属な列（変化 = 水準の差）は落とさない。落とすと木と列が変わり、§7 の比較（同じ列で3モデル）が崩れる。正則化に任せる
- 日付内で全銘柄が同じ値になる market 11列は、同じ日の順位付けには効かない（EDA）。線形では切片の日ごとの動きとして吸収される。そのまま入れる
