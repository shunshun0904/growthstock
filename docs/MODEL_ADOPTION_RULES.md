# 特徴量・設定の採否の規則（2026-09-21 に固定）

実験の結果を見てから規則を変えると、結果に合う規則を選ぶことになる。
以後の実験はすべてこの規則で判定し、変えるときは「次の実験から」にする。
この文書を書いた時点で、実験24 の確認実験（下の§4）はまだ回していない。

## 1. 変えないもの

| 層 | 中身 | 状態 |
|---|---|---|
| 目的変数（ラベル） | 1ヶ月内 +1.2σ / 終盤 +0.50倍 / MA5 ≥ MA20（`docs/MODEL_DESIGN.md`） | 変えない |
| 物差し | out-of-fold の上位10% の `ret_o1_20`（翌営業日寄り買い、20営業日後）の超過。窓は本番の out-of-fold と同じ（36ヶ月 / 6ヶ月 / 6ヶ月、エンバーゴ20営業日）。補助に `ret_o1_40` | 変えない |
| 比べ方 | 同じ行・同じパラメータ（本番の `lgbm_params.json`）・種3つの確率平均で A/B。探索は引き直さない（`docs/MODEL_TUNING_NOISE.md`） | 変えない |

## 2. 第1の規則: 平均を上げる特徴量

窓平均の差 z = (B − A) / √(SE_A² + SE_B²) > 2。
ノイズ床は 0.143pt（実験11、同一設定で種だけを振ったときの窓平均のレンジ）。
これまでどおり。

## 3. 第2の規則: ばらつきを減らす特徴量

第1の規則を満たさなくても、**次の4つを全部**満たせば採用する。

1. 勝ち窓が**全窓**。`ret_o1_20` と `ret_o1_40` の両方で
2. 最悪の窓が **0 以上**。両方の物差しで
3. 窓平均が下がっていない。z > −1（両方）
4. out-of-fold の PR-AUC が上がっている。改善幅は、同一設定で種だけを振った
   ときの PR-AUC の**レンジ**（実験25 で測る。3種平均の10通りの組み合わせの
   最大 − 最小）を超えること

4つとも「A と B を同じ行・同じ窓で比べたとき」の話。窓の数が 10 でも 11 でも
「全窓」を要求する。1窓でも負なら不採用。

なぜこの4つか
- 1〜2 は「外れる窓が無い」ことの直接の表現。実験24 の腕 B はこれを満たした
  （10/10、最悪 +0.05pt / +0.22pt）が、規則は結果を見た後に作ったので、
  そのまま採用の根拠にはしない（§4）
- 3 は「平均を犠牲にしてばらつきを減らす」特徴量を通さないため
- 4 は「当たる確率」が上がっていることの確認。実収益の窓は 10 しか無く、
  10/10 は偶然でも 1/1024 で起きる。PR-AUC は 16,000行で測るので、
  もう1本の独立に近い証拠になる

## 4. 実験24 の腕 B（開示からの日数）に対する一度だけの扱い

第2の規則は実験24 の結果を見てから作った。実験24 の数字に後追いで当てて
採用するのは、規則を先に決めた意味が無い。そこで**規則に依存しない確認**を
先に決めておく（実験26）。

- 種を 3 → 5 に増やす（42 / 7 / 123 / 2024 / 31337）
- 窓の区切りを **3か月ずらす**（学習開始を3か月遅らせて窓を切り直す。
  行・ラベル・物差しは同じ。境界だけが変わる）
- 元の窓（5種）と、ずらした窓（5種）の**両方**で、§3 の 1〜4 を全部満たしたら
  採用。どちらかで1窓でも負なら不採用（元の 10/10 は偶然と見る）

採用したら `build_dataset.py` に「直近の決算開示からの日数」と「直近の通期
開示からの日数」を足し、次の日曜の再学習から本番に入る。

## 5. 適用の順序

1. 特徴量1本ずつの検定（実験20 の方法）は**候補の絞り込み**にだけ使う。
   採否は決めない
2. A/B（§1 の比べ方）で §2 または §3 を満たしたら採用
3. 採用したものは、次の A/B の腕 A に入る（積み上げで判定する）
