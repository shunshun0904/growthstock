# 特徴量・設定の採否の規則（2026-09-21 に固定）

実験の結果を見てから規則を変えると、結果に合う規則を選ぶことになる。
以後の実験はすべてこの規則で判定し、変えるときは「次の実験から」にする。
この文書を書いた時点で、実験24 の確認実験（下の§4）はまだ回していない。

## 1. 変えないもの

| 層 | 中身 | 状態 |
|---|---|---|
| 目的変数（ラベル） | 1ヶ月内 +1.2σ / 終盤 +0.50倍 / MA5 ≥ MA20（`docs/MODEL_DESIGN.md`） | 変えない |
| 物差し | out-of-fold の上位10% の `ret_o1_20`（翌営業日寄り買い、20営業日後）の超過。窓は本番の out-of-fold と同じ（36ヶ月 / 6ヶ月 / 6ヶ月、エンバーゴ20営業日）。補助に `ret_o1_40` | 変えない |
| 比べ方 | 同じ行・同じパラメータ（本番の `lgbm_params.json`）・種3つの確率平均で A/B。探索は引き直さない（`docs/MODEL_TUNING_NOISE.md`） | 変えない |

## 2. 第1の規則: 平均を上げる特徴量

窓平均の差 z = (B − A) / √(SE_A² + SE_B²) > 2。これまでどおり。

ノイズ床の注意（実験25、2026-09-21）: 現行のラベル・物差し・本番パラメータで
種5つを振り直すと、窓平均のレンジは **0.59pt（1種）/ 0.67pt（3種平均の
10通り）**、標準偏差 0.26 / 0.22pt だった。docs に残る「0.143pt（実験11）」は
旧ラベル・出口40営業日で測ったもので、現行の設定には当てはまらない。
z の規則は窓の SE で割るので影響しないが、「差がノイズ床を超えた」と
言うときは 0.67pt を使う。

## 3. 第2の規則（改訂版、2026-09-21）: 分離力を上げる特徴量

第1の規則を満たさなくても、**次の4つを全部**満たせば採用する。

1. **out-of-fold の PR-AUC の改善が、種レンジの2倍を超える**（3種平均なら
   0.0048、実験25）。**3か月ずらした窓でも同じ**こと。これが「本物か」の
   判定。PR-AUC は 16,000行で測るので、10窓の平均より桁違いに解像度が高い
2. `ret_o1_20` の窓平均の差が **0 以上**。全期間と、**直近2年（判定時点で
   最新の4窓）**の両方で
3. `ret_o1_40` の窓平均の差が 0 以上（全期間）
4. 最悪の窓が A より **1.2pt 以上悪化しない**（種だけで動く幅。実験25 の
   3種平均で最悪の窓のレンジ 1.18pt）

2〜4 は「悪化していないか」の確認で、平均が上がる証拠としては使わない。
平均が上がる証拠は第1の規則で見る。

### 初版（撤回）と、なぜ変えたか

初版（同日）は「勝ち窓が全窓」「最悪の窓 ≥ 0」を要求していた。実験25 で、
同じモデルでも種を変えるだけで勝ち窓は ±1、最悪の窓は 1.2pt 動くと分かり、
窓1本の符号に依存する規則は種のくじ引きで結果が変わる。撤回した。

一方「平均が上がっていれば良い」だけにはしない。3種平均の窓平均は同じ
モデルでも 0.73〜1.40pt の間で散り（実験25）、A と B の差の種ノイズは
SD 約 0.31pt。効果ゼロでも「B の平均が上」は 50%、+0.27pt 以上は約 19% で
起きる。平均だけで採ると、種の偶然を半分の確率で採用する。

改訂は実験26 の結果を見た後に行った。**この改訂で採用した特徴量（§6）は
その事実ごと記録し、次の候補からは改訂版を先に固定した状態で判定する。**

## 4. 実験24 の腕 B（開示からの日数）に対する扱い

初版の規則に対して先に決めておいた確認（実験26: 種5つ、元の窓と3か月
ずらした窓）を回した。結果は §6。初版の規則では不採用、改訂版では採用。

## 5. 適用の順序と、探索し直し（B2）の扱い（2026-09-21 追記、実験27 の途中で固定）

1. 特徴量1本ずつの検定（実験20 の方法）は**候補の絞り込み**にだけ使う。
   採否は決めない。A/B に足す列は検定の結果で選ばず、先に決めた集合で回す
2. A/B は腕を3つ持つ。A（本番の列 / 本番のパラメータ）、B1（足した列 /
   同じパラメータ）、B2（足した列 / 5分割50試行で探索し直し）。
   本番は週次で探索をやり直すので、B2 が「本番で実際に起きること」
3. **採否は B1 で判定する**（§2 または §3）。B2 には次を追加で要求する
   - B2 の PR-AUC の改善が B1 と同じ向き（AUC は探索の引きに対して安定。
     実験27 の LightGBM で B1 +0.0169 / B2 +0.0168）
   - LightGBM（本番モデル）は B2 の探索の種を3つ引き、A 側も同じ3つの種で
     引き直して、**窓平均の分布**で比べる。B の3引きの平均が A の3引きの
     レンジの下端を下回ったら不採用（実験27b がこの形）
   - B2 の**1回の引き**の窓平均・最悪の窓は判定に使わない（引きだけで
     0.6〜1.5pt 動く。`docs/MODEL_TUNING_NOISE.md`）
4. モデルは LightGBM（本番）に加えて XGBoost / CatBoost / MLP を1引きずつ、
   ロジスティック回帰は探索なし（A と B1）で並べる。採否は LightGBM で決め、
   他モデルは「木のモデル全般で効くか / 線形では効かないか」の読み物
5. 採用したものは、次の A/B の腕 A に入る（積み上げで判定する）
6. **（2026-09-22 追記、実験27b の後。次の候補から適用）** LightGBM の
   3引きは、窓平均だけでなく**最悪の窓の平均**も比べる。B の3引きの最悪の
   窓の平均が A の3引きより 1.2pt 以上悪ければ不採用。実験27b で B が
   −2.32 → −4.22pt と悪化したのに、字面の規則では通ってしまったため

窓では `ret_o1_20` は 10/10 だが `ret_o1_40` が 7/9。不採用。

**改訂版の規則での判定: 採用。**

| 条件 | 元の窓 | 3か月ずらした窓 |
|---|---|---|
| 1. PR-AUC の改善 > 0.0048 | +0.0150 ○ | +0.0163 ○ |
| 2. `ret_o1_20` 窓平均の差 ≥ 0（全期間 / 直近2年） | +0.27 / +0.65pt ○ | +0.55 / +0.79pt ○ |
| 3. `ret_o1_40` 窓平均の差 ≥ 0 | +0.55pt ○ | +0.38pt ○ |
| 4. 最悪の窓が 1.2pt 以上悪化しない | −2.79 → −1.77pt ○ | +0.23 → +0.22pt ○ |

直近2年の窓ごとの差（B − A、`ret_o1_20`）: 元の窓 +1.26 / +0.25 / +1.03 /
+0.08pt、ずらした窓 +1.07 / +0.99 / +0.57 / +0.51pt。

読み方
- 実験24 の 10/10（3種）は、種を5つにすると 8/10 になった。**全窓で正の
  一部は種の偶然だった。** 確認実験を先に決めておいた意味はここにある
- 一方で PR-AUC の改善（+0.015 / +0.016）は種のレンジ（0.0024）の6倍あり、
  窓の切り方を変えても同じ大きさで出る。**分離力の改善は本物**。窓平均も
  4つの比較すべてで正（+0.27 / +0.55 / +0.69 / +0.38pt、z 0.4〜1.7）
- つまりこの特徴量は「当たる確率を上げ、平均を少し上げる」が、「外れる窓を
  無くす」ほどではない。第1の規則（z>2）にも第2の規則にも届かない
- 実験10（旧ラベル）の「平均は動かない」と整合する。今回は AUC の改善が
  新しく分かった点
- `ret_o1_40` が100行未満の末尾の窓（3か月ずらしたときの窓11）は両腕で
  除外した。行の有無で決めており、スコアは見ていない

採用後の実装: `build_dataset.disclosure_timing`（`days_since_disc` /
`days_since_fy`、実験24 と同じ定義）、`features.GROUPS["timing"]` を `all` に
追加した（2026-09-21）。

**その後（2026-09-22）: 探索込み・5モデルで測り直して見送りに変更**
（`docs/MODEL_DISCLOSURE_TIMING.md`）。分離力は5モデルで上がるが、探索を
引き直すと窓平均は上がらず（LightGBM 3引きの平均 +1.04 → +0.96pt）、
最悪の窓が悪化する（−2.32 → −4.22pt）。XGBoost / CatBoost / MLP でも
窓平均 −0.3〜−0.5pt。`timing` を `ALL_GROUPS` から外し、列はデータセットに
残す（研究用プリセット `all_timing`）。字面の規則（§3・§5）は LightGBM で
満たしていたが、最悪の窓の分布の条件が無かった（§5-6 に追記）。
