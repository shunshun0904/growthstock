# エントリータイミングの設計 — 新高値更新の「翌日いつ買うか」

## 0. この文書の位置づけ

既存モデル（`docs/MODEL_DESIGN.md`）が答えるのは **「この新高値更新は3ヶ月で伸びるか」**
という銘柄選定の問いだけである。買い方については何も言っていない。

運用は今こうなっている。

```
  場中      78週高値を更新した銘柄が候補になる
  引け後    モデルが採点し、順位と較正確率を出す          ← ここまでが既存
  翌営業日  …どこで買う？                                  ← ここが空白
```

この文書は、その空白を埋める層の設計である。**実装前に方法論の穴を潰す**ことが目的で、
`docs/MODEL_DESIGN.md` と同じ姿勢を取る。結論を先に3つ書く。

1. **この層が予測すべきは「上がるか」ではなく「いくらで買えるか」である。**
   上がるかは既存モデルが答えている。二度答えさせると、同じ情報で二重に賭けることになる。
2. **待つことの損得は、押し目の頻度と深さ（周辺分布）では測れない。**
   約定する事象と、その後のリターンは負に相関する。周辺分布で測ると待ちが必ず得に見える。
   必要なのは同時分布であり、それが「分布を推定する手法」を採る理由そのものである。
3. **分足の価値は「日足では約定順序が決まらない」一点に集約できる。**
   日足で楽観・悲観の両方の約定仮定を置き、結論が反転するなら分足に金を払う価値がある。
   反転しないなら払う必要がない。この判定を Phase 1 の出力として設計に組み込む。

## 1. 決めたい判断

翌営業日の扱いは3択である。

| 記号 | 方策 | パラメータ |
| --- | --- | --- |
| **A** | 寄り成行で買う | なし |
| **B** | 押し目に指値を置く | 深さ $d$、期限 $T$、期限到達時に追うか見送るか |
| **C** | 見送る | なし |

A が現状の想定（「始値が相当跳ねなければ、シンプルにそこでエントリー」）であり、
**この文書の全ての比較の基準**になる。A に勝てない方策は採用しない。

B は「押し目を狙う」の形式化である。$d$ と $T$ を決めないと方策にならない。
$T$ は「翌日の引けまで」「翌日の10:30まで」「3営業日まで」のいずれかを候補にする。

C は「跳ねすぎた」場合の退避先である。A/B のどちらも期待値が手数料を下回るときに選ぶ。

### 1.1 何を出力すれば意思決定になるか

出力は「上昇確率」ではない。**各方策の期待値と、その不確かさ**である。

```
  銘柄 7203  2026-09-11 の更新
    A 寄り成行     期待 +3.1%   90%区間 [-8.2, +15.6]   約定率 100%
    B -1.5%/引けまで 期待 +3.4%   90%区間 [-7.9, +16.1]   約定率  61%
    B -3.0%/引けまで 期待 +2.2%   90%区間 [-5.1, +12.0]   約定率  34%
    → A と B(-1.5%) の差は +0.3pt。区間が重なっており、待つ理由が無い
```

（上の数値は**書式の例であって実測ではない**。）

数字が並ぶだけでは判断にならないので、**差と、その差の不確かさ**を必ず併記する。
「+0.3pt だが区間が 0 を跨ぐ」と出れば、迷わず A を選べる。

## 2. 目的関数 — なぜ「いくらで買えるか」なのか

1回の売買の損益は

$$R \;=\; \frac{P_{\text{exit}}}{P_{\text{entry}}} - 1$$

で、この層が動かせるのは分母だけである。分子（手仕舞い）は既存ラベルの地平
（基準日から60営業日）に合わせて**全方策で共通の規則に固定する**。

> 固定しないと、入りと出を同時に動かすことになり、
> 改善がエントリーによるものか手仕舞いによるものか分離できない。

未約定のときは建玉が無いので $R = 0$ とする。損でも得でもない。
**この非対称性が設計全体を決める。** 待って外したときの罰は「損失」ではなく「不在」であり、
素朴に見ると罰が軽く見える。実際には逃したのは上昇そのものなので軽くない。

### 2.1 既存の実績値が基準価格を $C_t$ に置いていること

画面に出ているスコア帯の実績は**基準日の終値 $C_t$ を分母**にしている（`predict_daily.py`）。

| 出所 | 件数 | 正例率 | 終盤リターン中央値 | 同・平均 | 勝率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全体（out-of-fold） | 16,431 | 22.49% | +1.01% | +3.41% | 53.19% |
| 最上位スコア帯 | 1,643 | 36.82% | +3.56% | +4.80% | 63.60% |

【実測】`public/data/predictions.json` の `scoreBands`（平均は帯の件数で加重）

実際に買うのは翌営業日なので、**手にできるのはここから翌日のギャップを引いた残り**である。
最上位帯の平均 +4.80% に対して、翌日に +3% 窓を開けて始まれば残りは +1.8% 相当にしかならない。
エントリー価格を1%改善することは、全体の中央値リターン（+1.01%）を丸ごともう一つ積むのと同じ大きさになる。

**この層の効き幅は、既存モデルの効き幅と同じ桁にある。** 付け足しではない。

## 3. 待つことの損得は周辺分布では測れない（この設計の中心）

方策 B の期待値は

$$E[R_B] \;=\; \Pr(\text{約定}) \cdot E\!\left[R \mid \text{約定}\right] \;+\; \Pr(\text{未約定}) \cdot 0$$

ここで $E[R \mid \text{約定}]$ を $E[R]$ で代用してはいけない。約定するのは
**下げた銘柄**であり、下げた銘柄のその後は平均より悪い。逆に約定しなかった銘柄は
**下げずに走った銘柄**で、逃したのは一番良い部分である。バイアスは両方とも同じ向きに効く。

素朴な集計（「押し目は63%の日に来て、平均1.8%安く買える」）は、この2つを無視して
待ちを過大評価する。**やってはいけない分析の形を先に名指ししておく。**

### 3.1 損益分岐となる約定率

約定が中立（$E[R\mid\text{約定}] = E[R]$）という**最も待ちに有利な仮定**を置くと、
$d$ だけ安く買えたときの損益分岐は $P^\ast = m/(m+d)$ と閉じた形で書ける。

| 想定リターン $m$ | $d=0.5\%$ | $d=1\%$ | $d=2\%$ | $d=3\%$ | $d=5\%$ |
| --- | ---: | ---: | ---: | ---: | ---: |
| +3.41%（全体平均） | 87.2% | 77.3% | 63.0% | 53.2% | 40.6% |
| +4.80%（最上位帯平均） | 90.6% | 82.8% | 70.6% | 61.5% | 49.0% |

読み方: 最上位帯で「1%の押し目を待つ」方策が寄り成行に並ぶには、**82.8%の日で押し目が来る**
必要がある。来なければ負ける。しかも約定は中立ではなく不利な側に偏るので、実際の分岐点はこれより高い。

これは実測ではなく**恒等式**である。だが設計にとっては実測より重い。
押し目待ちは、直感に反して**かなり分の悪い賭け**から始まる。この表が
「押し目待ちはたぶん効くだろう」という前提を最初に壊しておくためにある。

### 3.2 だから同時分布が要る

必要なのは
$$p\big(\text{翌日の値動き},\ \text{その後60営業日の帰結}\ \big|\ \text{当日までの情報}\big)$$
であって、押し目の頻度でも深さでもない。分布を推定して期待値を積分する、という形が
**手段としてではなく必要として**出てくる。ベイズを使いたいからベイズを使うのではない。

## 4. 判断時刻を2つに分ける

使える情報が違うので、同じ「翌日の判断」でも別の問題になる。

| 記号 | 判断時刻 | 使える情報 | 指値の基準 | 分足が要るか |
| --- | --- | --- | --- | --- |
| **T0** | 寄り前（前夜〜08:59） | 前日引けまで | $C_t$ | 不要 |
| **T1** | 寄り後（09:05 / 09:30） | ＋始値と寄り後の数分〜30分 | $O_{t+1}$ | **要る** |

T0 は「前夜に注文を置いて寝る」形。T1 は「寄りを見てから決める」形で、
始値のギャップという**最も効きそうな1変数**を条件に入れられる。

ユーザーの現在の運用（「始値が相当跳ねなければ寄りで入る」）は、
実は T1 の判断を**しきい値1本で近似したもの**である。この層の最小の貢献は、
その「相当」をデータから決めることになる。

T0 と T1 は別モデルとして学習する。特徴量を共有させて「T1 のときだけ始値を足す」形にすると、
T0 の推論時に始値列を欠測で埋める運用になり、事故が起きやすい。分けるほうが安全である。

## 6. 段階の切り方 — なぜ日足10年が先か

分足は2年しかない。2年だけで方策を作ると、2024〜2026 という**単一局面に合わせた方策**が
できあがり、それを判別する手段が無い。既存モデルが10年・複数局面で学習しているのと
噛み合わない。

### 6.1 分解できるから分けられる

翌日の値動きを、日足で測れる**形**と、分足でしか測れない**時刻**に分ける。

$$p(\text{path}) \;=\; \underbrace{p\big(g,\ \ell,\ h,\ c \mid x\big)}_{\text{日足10年で推定}}\ \cdot\ \underbrace{p\big(\tau_\ell,\ \tau_h,\ \text{順序} \mid g,\ell,h,c,\ x\big)}_{\text{分足2年で推定}}$$

| 記号 | 定義 | 出所 |
| --- | --- | --- |
| $g$ | $\log(O_{t+1}/C_t)$ — ギャップ | 日足 |
| $\ell$ | $\log(L_{t+1}/O_{t+1}) \le 0$ — 始値からの最大下落 | 日足 |
| $h$ | $\log(H_{t+1}/O_{t+1}) \ge 0$ — 始値からの最大上昇 | 日足 |
| $c$ | $\log(C_{t+1}/O_{t+1})$ — 引けの位置 | 日足 |
| $\tau_\ell,\ \tau_h$ | 安値・高値が付いた時刻 | **分足のみ** |
| 順序 | 安値と高値のどちらが先か | **分足のみ** |

第1因子は10年で推定でき、次元も高い。第2因子は分足が要るが、次元が低く
（時刻の分布と2値の順序）、2年で足りる見込みが立つ。**2年制約が効くのは第2因子だけ**である。

これが「日足10年 → 分足2年」を選ぶ理由であり、単なる作業順序ではない。

### 6.2 段階

| Phase | 中身 | 分足 | 出るもの |
| --- | --- | :---: | --- |
| **0** | プローブ（**今回**） | — | 何が取れるかの実測。契約の要否 |
| **1** | 日足10年で方策比較。第1因子の推定と期待値評価 | 不要 | A/B/C の優劣。**5,500円/月を払うかの判断材料** |
| **2** | 分足2年で第2因子を足し、Phase 1 の結論が保つかを確かめる | 要 | 約定順序を解いた期待値。T1 の判断 |
| **3** | 日次パイプラインへ載せる | 要 | 候補ごとの方策と期待値 |

Phase 1 は**今の契約のまま全部できる**。ここで答えが出てしまう可能性があり、それはそれで良い結果である。

## 7. 予測層の設計（階層ベイズ）

### 7.1 何を推定するか

正規化してから推定する。既存ラベルがボラ正規化（$k=1.2\sigma$）を使っているので揃える。
揃えないと「値動きの荒い銘柄の押し目」と「静かな銘柄の押し目」を同じ $d$ で語ることになる。

$$\tilde g = g/\sigma_t,\quad \tilde\ell = \ell/\sigma_t,\quad \tilde h = h/\sigma_t,\quad \tilde c = c/\sigma_t$$

$\sigma_t$ は直近20営業日の日次リターン標準偏差（既存特徴量 `vol_20d`）。

### 7.2 なぜ階層か

1銘柄あたりの新高値更新イベントは、8年で平均すると数件しかない。
銘柄ごとに独立推定するとノイズを拾い、プールすると銘柄差が消える。
**部分プーリング**がこの件数域での正解になる。

ただし**銘柄IDの階層だけでは運用で使えない**。明日候補に挙がる銘柄は、
過去にイベントが1件も無いかもしれない。そこで階層は**属性**で切る。

| 階層 | 水準 | なぜ |
| --- | --- | --- |
| 市場区分 | プライム / スタンダード / グロース | 値動きの荒さと板の厚さが体系的に違う |
| 時価総額帯 | 既存の `cap_band` | 同上 |
| ボラ帯 | $\sigma_t$ の分位 | 正規化の残差が帯で偏る可能性がある |
| 銘柄 | ランダム効果（任意） | 既知銘柄では効く。新規銘柄は上位階層の事前分布に落ちる |

銘柄ランダム効果は**入れたうえで、新規銘柄には上位階層の分布を使う**。
階層モデルはこれが自然にできる。プールしない設計だとこの退避先が無い。

### 7.3 尤度

| 量 | 分布 | 理由 |
| --- | --- | --- |
| $\tilde g$ | Student-t | ギャップは両側に厚い裾を持つ。正規だと決算跨ぎを外れ値として捨てる |
| $-\tilde\ell$ | 対数正規 または ガンマ | 符号制約（$\ge 0$）がある |
| $\tilde h$ | 同上 | 同上 |
| $\tilde c$ | Student-t | 両側 |

4つは強く相関する（大きく下げた日は引けも安い）。**周辺分布を別々に置いて独立とみなすと
方策評価が壊れる**ので、潜在ガウスコピュラ（相関行列に LKJ 事前分布）で結合する。
$\ell \le c \le h$ のような順序制約は、変換後の潜在空間ではなく**サンプリング後に棄却**して扱う。

平均への説明変数 $x$（当日までの情報のみ）:
当日の終値位置、出来高比、ブレイクの抜き幅、20日リターン、$\sigma_t$、
既存モデルのスコア、地合い（TOPIX 20日/120日リターン）、決算開示の直後か否か。

> **決算開示の直後か否かは必ず入れる。** 決算跨ぎのギャップは分布が別物であり、
> 混ぜたまま推定すると、平時の押し目の深さを過大評価する。

### 7.4 実装と計算量

NumPyro（JAX）か PyMC。**GitHub Actions で回り切ることが採用条件**である。
既存の `Retrain Weekly` は40〜45分でタイムアウト180分。ここに MCMC を足すので、
4チェーン × 1,000サンプルが十数分で終わらないなら、
変分推論か、階層を減らすか、週次ではなく月次更新に落とす。**先に測ってから決める。**

依存は `research/requirements.txt` に足す。ブラウザ側とデータ取得側は
引き続き標準ライブラリのみで動く（この方針は変えない）。

### 7.5 必ず並べるベースライン

階層ベイズが**複雑さに見合うかを示せなければ採用しない**。同じ期待値計算機に
差し込めるものを3つ並べる。

| # | 手法 | 何を確かめるためか |
| --- | --- | --- |
| 1 | 経験分布（ボラ帯・市場区分で層化した過去の $(\tilde g,\tilde\ell,\tilde h,\tilde c)$ を復元抽出） | モデルが要るのかを確かめる。これに勝てなければ全部無駄 |
| 2 | 分位点回帰 LightGBM（10/25/50/75/90%） | 既存資産で足りるかを確かめる。相関は扱えないが速い |
| 3 | 階層ベイズ | 本命 |

3 が 1 と 2 に、**期待値の的中と分布の較正の両方で**勝って初めて採用する。
勝てないなら 1 か 2 を採る。ベイズを学ぶことと、ベイズを採用することは別に扱う。

### 7.6 較正の検証（これを出さない分布推定は意味がない）

- **PIT ヒストグラム**: 実現値の予測累積分布での位置が一様か。4つの量それぞれで見る
- **区間被覆**: 50% / 80% / 90% 区間に、実際にその割合が入るか
- **約定率の較正**: 予測した「$-d$ で約定する確率」を十分位に分け、実現約定率と突き合わせる。
  方策の期待値はこの1つの量にほぼ全てぶら下がっているので、**主たる較正指標はこれ**にする

## 8. 期待値の計算（方策の比較）

### 8.1 手順

1. 事後分布から $S$ 組のパラメータを引く
2. 各組から翌日の値動きを1本ずつ生成する
3. 生成した値動きの上で各方策を執行し、約定の有無と約定価格を決める
4. 手仕舞い価格（全方策共通）を当て、$R$ を得る
5. $S$ 本の $R$ の分布を方策ごとに作る

出すのは平均だけではない。**中央値、下側5%、約定率**を併記する。
平均だけだと「滅多に来ない大きな押し目で稼ぐ」方策が上に来て、実運用で耐えられない。

### 8.2 手仕舞い価格の扱い

$P_{\text{exit}}$ は既存ラベルの地平（60営業日）に合わせ、全方策で同一の規則にする。
エントリー価格が違えば同じ手仕舞い価格でもリターンが変わるので、比較は成立する。

**エントリー日がずれる方策（B で翌々日に約定など）では、手仕舞い日も同じだけずらすか、
基準日から固定するかで結果が変わる。** 基準日から固定する（保有期間が短くなる）を既定とし、
ずらした場合も併記する。どちらかに決め打つと、方策 B に有利/不利な偏りが入る。

## 9. コストと約定の仮定

入れないと押し目指値が必ず勝つ。**先に全部列挙して、あとから足さない。**

| 項目 | 扱い |
| --- | --- |
| 手数料 | 往復のパーセンテージを設定値にし、0.0% / 0.05% / 0.1% の3点で感度を出す。特定の証券会社の料率は書かない |
| 呼値 | 指値は東証の呼値単位に丸める。単位表は実装時に東証の公表資料を参照する（記憶で書かない） |
| 約定の判定（日足・悲観） | $L_{t+1} <$ 指値 − 1呼値 のときだけ約定。同値は約定しない（板の先頭に並べない） |
| 約定の判定（日足・楽観） | $L_{t+1} \le$ 指値 で約定 |
| 約定の判定（分足） | 分足の並びで、安値が高値より先に来たかを見て判定する |
| 寄り成行 | 寄付板寄せの価格で約定。始値＝約定価格とし、滑りは置かない |
| 流動性 | 想定建玉が「その日その価格帯の出来高」の一定割合を超える場合は約定しない扱いにする。候補には売買代金0.2億円級の銘柄が実際に出る |

**楽観と悲観の2つを常に並べて出す。** この2つの差が §12 の判断材料そのものである。

## 10. リーク・バイアスへの対処

| リスク | 対処 |
| --- | --- |
| 先読み | T0 は前日引けまで、T1 は始値＋寄り後 $m$ 分まで。特徴量の生成時刻をコードで検査する |
| 分割 | 既存に揃える（検証 2023-01-01〜 / テスト 2024-10-01〜）。分足フェーズは2年しかないのでテスト期間を別に切り、**日足フェーズの結論と食い違ったら分足側を疑う** |
| 銘柄の重複 | 同一銘柄の近接イベントは既存のクールダウン20営業日で抑えられている。分割の境界で同一銘柄が跨がないようにする |
| 生存バイアス | 上場廃止銘柄を除外しない。除外すると「消えた銘柄は買えなかった」ことにされる |
| 方策のパラメータ探索 | $d$ と $T$ は訓練期間だけで選ぶ。テスト期間の結果を見て選び直さない。選び直したら、それはテストではない |
| 多重比較 | $d \times T$ の格子を総当たりすれば、どれかは偶然勝つ。格子の大きさを事前に決め、勝者の効果量を格子数で補正した区間で報告する |

## 11. 評価指標と合格ライン

**先に決める。** 結果を見てから基準を作ると、どうとでも言える。

| 区分 | 指標 |
| --- | --- |
| 主 | 1トレードあたり平均リターンの、方策 A に対する差（手数料込み）。ブロック・ブートストラップの95%区間つき |
| 副 | 取り逃し率（未約定で終わった割合）／実現エントリー価格の平均改善／約定率の較正 |
| 健全性 | 局面別（2018調整・2020ショック・2021上昇・2022金利上昇・2023以降）の勝敗。1局面に依存していないか |

**合格ライン**

- 方策 B が A に対して **手数料込みで +0.3pt/トレード 以上**、かつ **95%区間が 0 を跨がない**
- 加えて、§9 の**楽観・悲観どちらの約定仮定でも符号が変わらない**

満たさない場合の結論は「押し目待ちは効かない。寄り成行に固定する」であり、
これは失敗ではない。**「エントリータイミングで損をしていない」ことが分かる**のは十分な成果である。

## 12. 分足を契約しないと決める条件

5,500円/月 を払うかどうかを、Phase 1 の出力だけで決められるように条件を書いておく。

| Phase 1 の結果 | 判断 |
| --- | --- |
| 楽観・悲観のどちらでも B が A に勝てない | **契約しない。** 寄り成行に固定して終わり |
| 楽観・悲観のどちらでも B が A に勝つ | **契約しない（当面）。** 日足だけで方策が立つ。分足は執行の精緻化として後回し |
| **楽観では勝ち、悲観では負ける（符号が反転する）** | **契約する。** 反転の原因は日中の到達順序が分からないことであり、分足はまさにそれを解く |
| B の優劣が、約定率の推定精度に強く依存する | **契約する。** 日中の出来高分布が約定率の推定を締める |

言い換えると、**分足の価値 ＝ 楽観仮定と悲観仮定の間の幅**である。
幅が結論をまたがないなら、その幅に金を払う理由がない。

## 14. 未検証の仮説（根拠つき・実測ではない）

設計の分岐点になる見込みを、根拠と一緒に残す。**どれも確かめていない。**

1. **新高値更新の翌日はギャップが上に偏り、その分だけ押し目待ちの分が悪くなる。**
   根拠: 母集団が「更新した銘柄」に条件付けられており、更新は買い需要の超過で起きる。
   §3.1 の分岐点表と合わせると、待ちはかなり不利な側から始まる。
2. **押し目の深さは、ブレイクの抜き幅よりも $\sigma_t$ に強く効く。**
   根拠: 既存モデルで `vol_20d` の寄与が最大級であること（`predictions.json` の寄与分解）。
   正規化を入れる設計上の根拠でもある。
3. **決算開示直後の更新は、それ以外と分布が別物になる。**
   根拠: ギャップの発生機序が違う（情報反映 vs 需給）。混ぜると平時の押し目を過大評価する。
4. **売買代金の小さい候補では、約定できても建てられない。**
   根拠: 直近の候補に売買代金 0.17億円の銘柄が実際に出ている（`predictions.json`）。
   分足の出来高分布で確かめられる。ETF が候補上位を占める既知の件（`docs/OPERATIONS.md`）と
   合わせて、母集団側の整理が先に要る可能性がある。
5. **寄り後30分の値動きは、その日の高値・安値の時刻を強く予告する。**
   根拠: 日中の出来高は寄り付きと引けに集中する形が知られている。
   これが成り立つなら T1 の判断が T0 より明確に良くなる。**分足が無いと確かめられない。**

## 15. 用語

| 語 | 意味 |
| --- | --- |
| 基準日 $t$ | 78週高値を更新した日。既存モデルが採点する日 |
| ギャップ | 翌日始値 ÷ 基準日終値 − 1 |
| 押し目の深さ $d$ | 指値を始値（T1）または前日終値（T0）から何%下に置くか |
| 期限 $T$ | 指値を出しておく時間。過ぎたら追うか見送るかを決める |
| 取り逃し | 指値が約定せず、その後上昇したこと |
| 部分プーリング | 群ごとの推定を全体平均へ引き寄せる。件数の少ない群ほど強く引き寄せられる |
| PIT | 実現値が予測分布のどこに位置したか。正しく較正されていれば一様分布になる |
