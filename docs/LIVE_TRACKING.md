# 実運用の追跡 —— 日次予測を OOF の見込みと比べる

`docs/PLAYBOOK.md` の「これから確かめること 1」（実運用の記録をつけ、
ここまでの推定が前向きにも成り立つかを確かめる）のための集計。
スクリプトは `research/live_track.py`、単体テストは `tests/test_live_track.py`。

## 結論を先に（2026-09-23 時点）

- **記録は 2026-09-11 から。** それより前（9/04〜9/10）は運用開始の日に
  まとめて出た版しか無いので数えない。9/11〜9/18 の6営業日で、規則どおりに
  買う日は **9/16 の1日だけ**。コーナン商事（7516）と山口フィナンシャル
  グループ（8418）を 9/17 の寄りで買ったことになる（9/18 の終値で
  −0.11% / +5.91%、どちらも途中）
- **取引の成績を比べられるのは、最初の取引が20営業日を迎える 2026-10-20 以降。**
  1〜2か月ぶん溜まる 11月下旬に最初の集計を出す（予約済み）
- **見込み（今の本番モデルの OOF に同じ規則を当てたもの）は、1取引 +2.20%
  （114件、SE 0.87、勝率 59%）、月あたり約 +1.35%**（枠3・複利なしの概算）。
  年ごとに +0.41〜+2.31%/月で、**月利3% に届いた年は無い**。2026年（1〜8月）は
  7件で −0.28%
  - PLAYBOOK の 141取引 +2.86%（実験35）とは2点が違う。あちらは実験27 の OOF
    （153列・種3つの平均）で、基準の90も**それ以前の窓の分布**で判定している。
    こちらは今の本番（205列・2026-09-20 学習）の OOF で、90 は画面と同じく
    **OOF 全体の分布**で判定する。実運用と比べる相手としてはこちらが正しいが、
    差がどちらの違いから来ているかは分けて測っていない
- **早めに見えた兆候（まだ結論ではない）**: 実運用の1週間で、3モデルとも
  90以上だった候補の割合が 11.8%（OOF で同じ長さの期間を切り出すと中央値 2.0%、
  90%点 8.7%）。LightGBM と CatBoost が 90以上とした割合も 23.5% / 27.5%
  （OOF の中央値 7.5% / 6.8%）。通過は 9/16 の1日に集中しており1週間では
  判断できないが、本番モデルのスコアが OOF より高めに出ているなら、画面の
  「90以上」は OOF で確かめた線より緩いことになる。集計のたびにここを見る

## 何と何を比べるか

| | 実運用 | 見込み |
|---|---|---|
| 元のデータ | git の履歴にある `public/data/predictions.json`（日次予測が毎日コミットする） | 本番モデルの OOF（Release の `oof.parquet` / `xgb_oof.parquet` / `cat_oof.parquet`） |
| その日の判断 | **翌営業日の寄り（9:00 JST = 0:00 UTC）より前の最後の版**。寄りまでに版が無ければ最初の版を使い「遅れ」と記す | 同じ規則を全期間に当てる |
| 百分位 | 画面に出ていた値（その時の本番モデルの OOF に対する位置） | 画面と同じ式（OOF 全体のうち、そのスコアより低い割合） |
| 値動き | 保存済みの日足（分割調整後） | 同じ |

規則は画面（`src/lib/strategy.js` の `STRATEGY`）と同じ値で、単体テストが両者を突き合わせる:
発火8件未満の日は買わない / 3モデルすべて90以上 / 3モデルの最小の百分位の順に上位2件 /
翌営業日の寄りで買う / +20% の指値、届かなければ20営業日 / 同時に3銘柄まで・先着順。

収益の数え方は OOF の実験（実験32〜35）と同じ。+20% は買った日（1営業日目）の高値から見て、
届けば +20% ちょうど。届かなければ20営業日目までの5日平均終値（`ret_o1_20`）。参考に
「20営業日目の終値で売った場合」も並べる。手数料・税・スリッページは含まない。

作ったときに2つ突き合わせてある:

- 届かなかったときの収益は、OOF ファイルの `ret_o1_20` と全16,220行で一致（差の最大 4e-14）
- 枠の回し方は実験35 の `simulate` と同じ取引114件（同じ銘柄・同じ平均）

### 1本の数字と比べない

見込みを OOF 全体の平均1つにしない。**実運用と同じ長さの期間を、OOF の中で21営業日
（約1か月）ずつずらして切り出し**、期間ごとの成績の散らばりを見込みの幅にする。
実運用の値がその 10〜90% の中なら「見込みの幅の中」、外なら「上 / 下」と出す。
1つの OOF で戦略を決めると過適合する、という運用者の方針に合わせた比べ方。

### 途中の取引は平均に入れない

+20% に早く届いた取引だけが先に確定するので、確定した取引だけで平均を取ると
勝ち側に偏る。**選定日から20営業日が過ぎた日の取引だけ**を成績に数え、
それより後の取引は「途中」として含み損益だけ出す。枠の埋まり方は途中の玉も含めて回す。

## 回し方

- **GitHub Actions**: 「Run Experiment」を ref `claude/jquants-browser-app-bwk19a`、
  exp `live_vs_oof.py` で起動する。Release の日足と本番の OOF を落とし、
  ラベル付きのデータセットを作ってから回る（ラベルは分離力の欄に使う）。
  checkout は浅いので、予測の履歴はスクリプトが `git fetch --unshallow` で取り寄せる。
  結果は実行の Summary に出る。本番の設定には何も書かない
- **手元**: `python3 research/live_track.py`（`research/_data` に日足・カレンダー、
  OOF は `--oof-dir` で場所を渡す）。`--since 2026-09-11` で起点を変えられる。
  `--json out.json` で要約を書く

## 読み方

| 欄 | 中身 |
|---|---|
| 結論 | 記録の範囲、見込み、実運用の成績（数えられる取引があれば）、選定の頻度、分離力 |
| 1. 記録の状況 | 予測ファイルの版の数、数えない日、寄りに間に合わなかった日 |
| 2. 日ごとの判断 | 発火数・通過数・判断・買う銘柄と、判断に使った版・その時刻・モデルの学習日 |
| 3. 取引 | 規則どおりの売買。買った日・買値・状態（+20%到達 / 満了 / 保有中 / 枠が満杯）・収益・含み |
| 4. 見込みとの比較 | OOF 全体と年ごとの成績。(a) 選定の流れ（発火数・基準を満たす割合・モデルごとの90以上の割合・買う日の数）、(b) 取引の成績、(c) 枠を気にしない場合（基準通過すべて）、(d) 分離力（ROC-AUC） |

- **(a) の「90以上の割合」は OOF 全体では定義上 10%。** 本番モデルは全期間で学習して
  いるので、スコアの水準が OOF とずれるとここが動く。実運用で基準を満たす候補が
  OOF より多い（少ない）なら、線が OOF で確かめたものより緩い（きつい）ことになる
- 取引が少ないうちはどの数字も幅が広い。1取引の標準偏差は約9pt で、10件の平均でも ±3pt はぶれる
- 紙の上の売買なので、実際の約定は入っていない。実際の売買はスプレッドシートの台帳の
  「建値・株数・手仕舞い日・手仕舞い値・損益」の列に記録する（集計にはまだ入れていない）
